# 팀원 코드 수정 설명 — 2026-09-09

기존 스킬과 UI를 멀티플레이에서도 정확한 플레이어에게 연결하기 위한 코드 변경입니다. 변경 기준일은 2026년 9월 9일입니다.

여기서 **서버**는 여러 사람의 요청을 받아 게임 결과를 최종 확정하는 실행 프로그램입니다. Host로 플레이하면 방장의 게임이 이 일을 함께 합니다. **연결 함수**는 화면이나 스킬에 “지금부터 이 플레이어의 정보를 사용해 주세요”라고 지정하는 함수입니다.

## 1. 병헌님: 캐릭터 능력치를 읽는 순서

파일: `Assets/WBHTest/Scripts/Player/WBH_PlayerStatus.cs`

**기존 문제**: 캐릭터가 만들어질 때 이동 코드가 먼저 이동속도를 물어보는데, 능력치를 준비하는 코드가 아직 실행되지 않을 수 있었습니다. 같은 캐릭터를 다시 연결할 때 능력치 변경 알림이 여러 번 등록될 가능성도 있었습니다.

**바꾼 부분**: 능력치를 읽기 전에 자신의 매니저를 준비하도록 했습니다. 변경 알림을 다시 연결할 때는 이전 연결을 먼저 해제합니다. 이미 만들어진 능력치와 체력·마나를 새 값으로 초기화하지 않습니다.

**달라지는 점**: 생성 순서가 달라도 이동속도 등을 읽을 수 있고, 재연결 때문에 같은 변경 처리가 중복되는 것을 막습니다. 공격력 공식이나 체력 최대값을 바꾼 작업은 아닙니다.

## 2. 병헌님: 화상 사망과 상태이상 이펙트

파일: `Assets/WBHTest/Scripts/StatusEffect/WBH_EnemyStatusEffectController.cs`

수정은 두 부분입니다.

1. **화상 피해**: 숫자만 전달하던 호출을 `WBH_DamageResult`에 담아 전달하도록 바꿨습니다. 기존의 숫자만 받는 경로는 체력을 줄여도 정상 사망 처리까지 이어지지 않았습니다. 기존 전투의 피해·사망 처리 입구를 이용하도록 연결한 것입니다. 화상 피해량이나 틱 간격을 바꾸지는 않았습니다.
2. **이펙트가 없는 서버**: 상태이상 이펙트를 재생할 장치가 없으면 화면 효과만 생략합니다. 화면이 없는 서버에서도 화상·감속 같은 게임 규칙은 계속 처리할 수 있습니다.

`WBH_DamageResult`는 구조체입니다. 여기서 `new`라고 쓴다는 이유만으로 매 틱마다 별도의 힙 객체와 가비지가 생기는 것은 아닙니다. 사망 처리에도 기존 피해 경로를 사용합니다.

## 3. 우진님: 내 패시브가 내 캐릭터에게만 적용되도록

파일: `Assets/WJ_TestPlace/Script/Player/PlayerStatManager.cs`

**기존 문제**: 능력치 계산이 한 개의 전역 패시브 프로필을 읽었습니다. 멀티에서는 A와 B의 투자 내역이 다르므로 같은 프로필을 함께 읽으면 안 됩니다. 초기화가 반복되면 기존 능력치 객체를 새로 만들 수도 있었습니다.

**바꾼 부분**: 이미 준비된 능력치는 그대로 재사용하는 `EnsureInitialized()`와, 해당 플레이어의 패시브 수치를 받는 `SetPassiveStats(...)`를 추가했습니다. 싱글 캐릭터는 기존 프로필을 사용합니다. 네트워크 캐릭터는 서버가 전달한 자기 패시브를 사용합니다.

**예시**: A만 공격력 패시브에 투자했다면 A의 공격력만 올라갑니다. 상점처럼 파티가 함께 쓰는 혜택의 최고 투자자 규칙은 별도의 기존 상점 연결에서 처리합니다.

## 4. 우진님: 파이터·거너 스킬에 조준값을 전달

파일:

- `Assets/WJ_TestPlace/Script/Player/Skill/FighterSkillController.cs`
- `Assets/WJ_TestPlace/Script/Player/Skill/GunnerSkillController.cs`

**기존 문제**: 스킬이 실행되는 컴퓨터의 마우스와 카메라를 직접 읽었습니다. A가 왼쪽을 클릭해도 방장 컴퓨터에서 실행하면 방장의 마우스를 읽을 수 있었습니다. 화면이 없는 서버에서는 카메라가 없어서 실패할 수도 있었습니다.

**바꾼 부분**: 기존 스킬 함수에 “조준 방향, 목표 위치, 이 캐릭터의 능력치”를 전달할 수 있는 입구를 추가했습니다. 싱글의 기존 입력 함수는 유지했습니다. 요청값이 잘못되면 마나를 쓰기 전에 거절합니다. 스킬을 시작할 때 받은 방향을 실제 타격·대시·폭탄 실행에서도 사용합니다.

파이터에는 차징 시작·해제를 외부에서 요청하는 함수도 추가했습니다. 두 캐릭터 모두 연결 끊김·사망 등으로 진행 중 스킬을 중단할 수 있게 했습니다. 중단한다고 이미 쓴 마나를 돌려주거나 이미 발사된 탄을 없애지는 않습니다. 효과 크기를 표시하는 쪽에서도 기존 계산값을 읽을 수 있게 했습니다.

**달라지는 점**: 기존 스킬의 범위·피해·진화 로직을 서버에서 재사용합니다. 별도의 멀티용 스킬 공식을 다시 만들지 않습니다. 이번 4인 검사에서 파이터 12조합과 거너 12조합을 실행했습니다. 파이터 차징의 6회 타격, 이동 전용 대시, 거너 백스텝 후 조작 복귀를 확인했습니다.

## 5. 우진님: 스킬 창이 다른 사람을 바꾸지 않도록

파일: `Assets/WJ_TestPlace/Script/Player/Skill/SkillPopupController.cs`

**기존 문제**: 창이 씬에서 먼저 발견한 스킬 컨트롤러를 사용했습니다. 네 명이 있으면 그것이 내 캐릭터라고 보장할 수 없습니다.

**바꾼 부분**: `Bind(...)`로 창이 사용할 스킬 대상을 지정합니다. 내 캐릭터와 연결이 끊기면 다른 캐릭터를 대신 찾아서 조작하지 않습니다.

**달라지는 점**: 내 창의 진화·강화 선택은 내 플레이어의 서버 요청으로 갑니다. 외부 연결을 사용하지 않는 싱글은 기존 자동 검색을 유지합니다.

## 6. 우진님: 퀘스트 계산은 함께 쓰고 지급은 서버에서

파일: `Assets/WJ_TestPlace/Script/Quest/QuestManager.cs`

**기존 문제**: 진행도를 세는 기능과 로컬 플레이어에게 보상하는 기능이 한 흐름에 묶여 있었습니다. 멀티에서 그대로 호출하면 파티의 진행도와 각자의 보상을 구분하기 어려웠습니다.

**바꾼 부분**: “진행도 만들기”, “조건에 맞으면 숫자 올리기”, “모든 조건을 달성했는지 확인하기”를 다른 코드에서도 사용할 수 있게 했습니다. 이 함수들은 돈을 주거나 저장하지 않습니다. 싱글도 같은 계산 함수를 사용합니다.

**예시**: 파티가 로봇을 한 대 잡으면 서버가 공유 진행도를 한 번 올립니다. 완료 뒤 A와 B에게 각각 보상하는 일은 SW의 멀티 퀘스트 코드가 맡습니다. 가방이 가득 찬 사람의 보상을 대기시키는 것도 그쪽 책임입니다. 원본 퀘스트 매니저 전체를 멀티용으로 바꾼 것은 아닙니다.

파일: `Assets/WJ_TestPlace/Script/Quest/QuestBoardNPC.cs`

**바꾼 이유**: 기존 NPC 창과 버튼을 계속 사용하면서, 버튼을 누른 것만으로 퀘스트를 즉시 확정하지 않게 하려는 목적입니다.

**바꾼 부분**: 대화·리롤·수락 요청을 서버로 보내는 연결을 추가했습니다. 서버가 확정한 퀘스트와 방문별 사용 여부를 받아 화면에 반영합니다. 싱글의 기존 대화 방식은 유지합니다.
