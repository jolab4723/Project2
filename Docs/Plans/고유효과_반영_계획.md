## 4. 구현 방법

### 4-1. 공통 경로 (행동형 효과 추가 절차)

1. SO: `Assets/SW/Scripts/Equipment/Effects/{Name}UniqueEffectSO.cs`(수치만 보관, 파일명=클래스명).
2. 임포터: `UniqueEffectTableSOImporter.cs`의 `ResolveEffectType`, `ApplyRow`, `ValidateRows`, 엑셀 ComboBox 시트 등록. **WJ 영역 — 승인 필요.**
3. 데이터: `UniqueEffectTable.xlsx`의 해당 행 `effectType`·계수 변경, `UniqueEffectLabel.xlsx` 4개 언어 설명 갱신. **WJ 관리 원본 — 승인 필요.** 변경 후 `DataLoader/Item Data Table/0. Run All Steps`.
4. 런타임: `PlayerItemEffectState` partial 파일 추가. `CanExecute`로 실행 제한, 쿨다운은 `GetCooldownSeconds`/`GetCooldownKey`, 정리는 `ResetAttackLifetime`/`ReconcileEquipment`.
5. 진입점: 회피·피격은 `ItemTriggerManager`(싱글)와 `NetworkItemTriggerManager`(멀티), 처치·치명타는 기존 `PlayerItemEffectState` 발동 경로.
6. 연출: `PlayerItemEffectState` event → 싱글은 `UniqueEffectPresentation` 구독, 멀티는 `NetworkItemTriggerManager`가 서버에서 구독해 ClientRpc로 같은 `Present*` 호출. 프리팹은 `Assets/SW/Resources/UniqueEffectVFX/UEVFX_*.prefab`.

### 4-2. 신규 범용 타입

| 타입(가칭) | 데이터 필드 | 재사용 |
|---|---|---|
| `TriggeredRestoreUniqueEffectSO` | 발동 조건(TriggerCondition), 대상(HP/MP), 양(고정값 또는 최대치 %), 쿨타임, 연출 색 | HP는 `PlayerHealthManager`, MP는 `PlayerManaManager`. 서버 권한 경계는 기존 회복 경로(포션)와 같은 방식 |
| `TriggeredShieldUniqueEffectSO` | 발동 조건, 보호막량(고정 또는 최대 체력 %), 지속시간, 쿨타임 | `PlayerArmorEffectRuntime.GrantShield`와 SolarGrace 보호막 표시·SyncVar |

- 새 전역 Manager나 Singleton은 만들지 않는다. 기존 발동 경로에 타입 분기만 추가한다.

## 5. 단계별 진행

각 Phase의 완료 조건 공통: Unity 컴파일·Console 신규 오류 없음 → 하네스 해당 효과 통과(싱글·호스트) → 연출 캡처 검수 → `/ponytail` → `/code-review` → 개인 구현 로그 기록.

| Phase | 내용 | 완료 기준 |
|---|---|---|
| 0 | 검증 하네스 구축. Assets 밖 Editor `run_script`로 효과별 아이템 장착 → 발동 조건 강제(적중·치명타·처치·회피·피격·체력 임계) → 스탯·피해·버프·이벤트·SyncVar 확인. 싱글 처치 발동 누락 위험(`WBHEnemyItemDropAdapter` 미부착 적) 확인 | 현재 100개의 기준 결과표(통과/실패/해당 없음) 확보 |
| 1 | 발동형 회복 타입 + 4개 재구현 + 회복 연출 | 4개가 싱글·호스트에서 같은 회복량, 쿨타임 준수, 툴팁 문구 일치 |
| 2 | 발동형 보호막 타입 + 2개 재구현 + 보호막 연출 | 보호막 흡수량·지속시간·중첩 규칙이 SolarGrace와 충돌하지 않음 |
| 3 | PortalCloak 투사체 통과 + 연출 | 통과 시간 동안 적 투사체 피해 0, 근접·장판 피해는 정상, 싱글·호스트 동일 |
| 4 | ClownsTrick 혼란 상태이상 + 연출 | 반경 내 적의 이동이 지속시간 동안 반전, 보스·엘리트 적용 규칙 결정 반영 |
| 5 | 연출 보강 1~4 | 격리 프리뷰 + 정식 `Act1_` 맵 캡처에서 발동 순간 식별 가능 |
| 6 | 연출 보강 5~6 | 위와 같음, 절차적 선 제거 후 프리팹 연출로 대체 |
| 7 | 문서 정리 | SW 담당 문서의 깨진 링크(`김성우.md` §341의 `Project2_Weekend_Work_Progress_2026-10-05.md`) 정리, 하네스 최종 결과표 첨부 |

- Phase 1~4는 서로 독립이라 병렬 가능하다. 단, 같은 `PlayerItemEffectState` 파일을 동시에 고치지 않도록 각 Phase는 자기 partial 파일만 추가한다.
- Phase 0은 모든 Phase의 기준선이라 가장 먼저 한다.

## 6. 연출 제작·검수 기준

- 제작 순서: 기존 `UniqueEffectVFX` 프리팹과 VFX 팩을 복제·변형(원본 수정 금지) → 부족하면 Blender로 메시·셰이더·파티클 제작 → Unity 프리팹화.
- 검수 통과 기준: 플레이어가 "언제 발동했는지"를 화면에서 알아볼 수 있을 것. 격리 방향광 프리뷰와 정식 `Act1_` 맵의 실제 광원·Bloom 조건에서 캡처 비교.
- 멀티: 같은 연출이 호스트와 원격 클라이언트에서 모두 재생되는지 확인.
- 발광 품질은 AGENTS.md 3-1절의 머터리얼·발광 기준을 따른다.
