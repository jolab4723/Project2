## 3. 커리큘럼

| 순서 | 단계 | 완료 조건(조건 타입) | 사용할 기존 이벤트·상태 |
|---|---|---|---|
| 1 | 이동(우클릭) | 지정 구역 진입 | `TutorialZone` |
| 2 | 기본 공격(좌클릭, 허수아비) — 클래스별 문구 | Attack 상태 3회 진입 | `WBH_PlayerStateMachine.OnEnterState` |
| 3 | 회피(Space) | Dodge 상태 1회 | `WBH_PlayerStateMachine.OnEnterState` |
| 4 | 스킬(A/S/D/F) | Skill 상태 1회 | `WBH_PlayerStateMachine.OnEnterState` |
| 5 | 실전 웨이브 | 웨이브 완료 | `WBH_EnemySpawnManager.WaveCompleted` |
| 6 | 장비 줍기 | 고정 드랍 장비 획득 | `InventoryController.OnItemAdded` |
| 7 | 장비 장착(I, 우클릭 또는 끌기) | 지정 장비 장착 | `EquipmentSystem.OnEquipmentChanged` |
| 8 | 포션 줍기·장착 | 빨간 물약 획득·장착 | 6·7과 같음 |
| 9 | 포션(Q) | 충전 감소 | `PotionUseManager.CurrentCharges` |
| 10 | 포탈로 종료 | 포탈 진입 | `TutorialZone` |

- 2026-10-19 변경: 새 런에는 포션이 장착되어 있지 않아 포션 단계를 장비 장착 뒤로 옮겼다. 허수아비 적중은 상태 전이(Attack)로 판정해 WJ `TrainingDummyStatus` 수정이 필요 없어졌다.
- 6단계 드랍 장비는 고유효과가 없는 장비로 확정했다: Fighter `item.weapon.greatsword.sharpgreatsword`, Gunner `item.weapon.rifle.fieldmod`.
- 상점, 패시브, 스테이지 맵, 캠프, 강화는 튜토리얼에서 빼고, 실제 게임에서 처음 만날 때 한 번 짧은 힌트로 안내한다(Phase 4).

## 4. 구조

```
TutorialStepSO (데이터)
  ├─ labelKey, highlightTarget 경로, showDim, 클래스 필터(Fighter/Gunner/공통)
  └─ 완료 조건 1개 (조건 타입 + 파라미터)

TutorialConditionSO 계열 (데이터, 조건 타입마다 하나)
  └─ 예: ZoneEnter, StateEntered(Attack/Dodge), SkillUsed, PotionUsed,
         WaveCompleted, ItemAcquired, ItemEquipped, DummyHit

TutorialRunner (씬 컴포넌트, SW)
  ├─ 단계 목록을 순서대로 실행, 조건 객체를 구독/해제
  ├─ 화면 표시는 KY_TutorialOverlay에 위임(문구·하이라이트)
  └─ 종료 시 완료 플래그 저장 → 다음 씬으로 이동
```

- 조건 판정은 플레이어 참조를 러너가 주입한다(`PlayerContext`). `Find`나 새 전역 참조를 퍼뜨리지 않는다(AGENTS.md 4절).
- 오버레이의 `Time.timeScale = 0`은 안내만 보여 주는 단계에서만 쓰고, 행동을 기다리는 단계는 시간 정지 없이 문구만 띄운다.
- 단계 추가·수정은 SO 에셋 편집만으로 가능해야 한다.

## 5. 진입·이탈 흐름

| 경로 | 흐름 |
|---|---|
| 최초 자동 진입 | 캐릭터 선택 → 완료 플래그 없음 → 튜토리얼 씬(선택 캐릭터, 격리 런) → 완료 또는 건너뛰기 → 완료 플래그 저장 → 기존 새 게임 흐름(`BeginNewGame` → StageSelect) |
| 타이틀 재진입 | 타이틀 "튜토리얼" 메뉴 → 캐릭터 선택 → 튜토리얼 씬 → 종료 시 타이틀 복귀(진행 중 런은 건드리지 않음) |
| 건너뛰기 | 오버레이의 건너뛰기 → 확인 → 완료 플래그 저장 후 위와 같은 다음 단계로 이동 |

- 격리 방식: 튜토리얼 씬은 `DataManager`의 런 저장(`SaveGameplayData`)과 퀘스트 저장을 호출하지 않는 전용 초기화 경로를 쓴다. 기존 `YJ_StageSaveService.BeginTemporaryRun`과 같은 "세션 전용 상태" 방식을 따른다.
- 검증 시 튜토리얼 전후의 저장 파일(`profile_singleplayer.json`, `gamesave.json`, 퀘스트 저장)을 비교해 완료 플래그 외 변경이 없는지 확인한다.

## 6. 단계별 진행

각 Phase의 완료 조건 공통: Unity 컴파일·Console 신규 오류 없음 → Fighter·Gunner 각각 실제 플레이 → `/ponytail` → `/code-review` → 개인 구현 로그 기록.

| Phase | 내용 | 완료 기준 |
|---|---|---|
| 0 | 완료 플래그 저장 필드 추가와 최초 실행 판정 | 새 계정은 미완료, 플래그 저장·로드·Firebase 동기화 후에도 유지 |
| 1 | 진행 엔진: `TutorialStepSO`, 조건 타입, `TutorialRunner`, 오버레이 연결, 라벨 키 | 테스트 단계 목록으로 조건 충족 → 다음 단계 전환이 동작 |
| 2 | 튜토리얼 씬 제작: 지형, 플레이어 스폰, 허수아비, 튜토리얼 웨이브, 고정 드랍, 포탈 | Fighter·Gunner로 1~9단계를 끝까지 진행 가능 |
| 3 | 진입·이탈 흐름 연결(최초 자동, 타이틀 메뉴, 건너뛰기) | 3가지 경로 모두 의도한 씬으로 이동, 저장 파일 비교에서 완료 플래그 외 변경 없음 |
| 4 | 첫 만남 힌트(상점, 패시브, 스테이지 맵, 캠프, 강화) | 각 힌트가 계정당 한 번만 표시 |
| 5 | 다국어 라벨 4개 언어, Build Settings 등록 | 언어 전환 시 모든 문구 표시, 빌드 씬 목록 등록(팀 공용 변경으로 사전 공지) |

- Phase 0과 1은 독립이라 병렬 가능. Phase 2는 1 이후, Phase 3은 0·2 이후.
- 진행 상태(2026-10-19): Phase 0~3 완료. Phase 5 중 Build Settings 등록과 타이틀 버튼 라벨(`title_ui.tutorial`, 4개 언어)은 Phase 3에서 처리했다. 남은 것은 Phase 4와 튜토리얼 단계 문구의 4개 언어 라벨이다.
- Phase 3 구현: `TutorialEntry`(정적 진입·이탈 규칙)가 최초 실행 판정과 진입을 맡는다. 최초 실행은 이어할 런이 없고 완료 플래그와 정산 기록이 모두 없는 프로필이다. 최초 자동 진입은 `BeginNewGame` 뒤에 튜토리얼로 가고 종료 시 StageSelect로 간다. 타이틀 메뉴 진입은 새 게임을 만들지 않고 종료 시 타이틀로 돌아간다. 타이틀 요청은 캐릭터 선택 화면을 떠나면 버린다.
- 플레이 피드백 반영(2026-10-19): 설명창 재디자인, 완료 안내 단계 추가(총 13단계), 허수아비 체력바 방향 수정과 웨이브 시작 시 숨김, 맵을 배치안 v2의 "칼바람 다리"로 교체.

## 7. 결정 필요 사항

| 항목 | 내용 | 제안 |
|---|---|---|
| 기존 플레이어 처리 | 완료 플래그가 새로 생기면 기존 계정도 "미완료"로 읽힌다 | 이미 플레이 기록이 있는 프로필(플레이 시간 > 0 또는 정산 기록 있음)은 완료로 간주해 자동 진입하지 않음 |
| 타이틀 재진입 시 캐릭터 | 타이틀에서 들어갈 때 어떤 캐릭터로 할지 | 기존 싱글 캐릭터 선택 화면을 재사용 |
| 튜토리얼 웨이브 구성 | 적 종류·수·난이도 | 일반 근접 2~3기, 원거리 1~2기 수준의 낮은 난이도 |

## 9. 위험과 확인 사항

- `BeginNewGame`은 `gamesave.json`을 새로 쓴다. 튜토리얼을 새 게임 이전에 끼워 넣을 때 기존 런을 덮어쓰지 않도록 순서를 지킨다.
- 오버레이의 시간 정지가 행동 대기 단계에서 걸리면 진행이 막힌다. 단계 데이터에 시간 정지 여부를 둔다.
- 튜토리얼 씬에서 싱글 전투 코드(`YJ_StageManager` 등)가 저장을 호출하지 않는지 확인한다.
- 멀티 경로에서는 튜토리얼이 절대 실행되지 않아야 한다(`MirrorNetworkManager.OwnsGameplay`일 때 진입 차단).
