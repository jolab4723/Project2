# UI 검수 점검표 (Project2) v1

- 작성: 김성우(SW), 2026-10-19
- 쓰는 곳: 게임 UI를 고치거나 새로 만든 뒤, 사용자에게 보여 주기 **전**. 순서는 자동 검사 → 독립 검토(`ui-reviewer`) → 작업자 직접 확인 → 사용자다.
- 판정은 사용자 눈을 대신하지 않는다. PASS도 "사용자 확인 대기"로 쓴다.
- 사용자에게 보내는 캡처는 마지막 수정 **뒤에** 새로 찍은 것만 쓴다.
- 이 게임은 다크 SF 톤의 3D 탑다운 핵앤슬래시다. 픽셀아트 기준(정수 픽셀 격자, 12px 픽셀 글꼴)은 적용하지 않는다.

## 1. 자료 (매번 새로 만든다)

| 자료 | 만드는 법 |
|---|---|
| 자동 검사 결과 | 재생 중 `unity command eval_file --file ~/.claude/skills/ui-review/scripts/ui_audit.cs`. 글자 넘침, 배경 밖, 화면 밖, 형제 겹침, 작은 버튼을 본다. 좌표는 640×360 환산값이다 |
| 화면 캡처 2종 | Game 뷰 크기를 실제로 바꿔 `ScreenCapture.CaptureScreenshot`으로 **1920×1080**과 **2340×1080(모바일 비율)** 을 찍는다. `capture_game_view --width/--height`는 이미지를 늘려 저장하므로 비율 판단에 쓰지 않는다 |
| 비교 기준 캡처 | 새 UI만 보지 않는다. 같은 화면에 함께 뜨는 HUD와 기존 팝업(일시정지·설정·상태·스킬·인벤토리·퀘스트·패시브·버프·휴식)을 함께 찍어 톤을 비교한다 |
| 상태별 캡처 | 필요할 때: 버튼 있음/없음, 비활성, 선택, 마지막 단계처럼 모양이 바뀌는 상태 |

## 2. 판정 순서

1. **자동 검사**: 새로 만들거나 고친 UI에서 나온 건수가 0인가. 기존 UI에서 나온 건은 따로 표시하고 이번 판정에서 빼되 보고에는 남긴다. 의도한 겹침은 이름 끝을 `Band`/`Rule`/`Accent`로 두어 검사에서 뺀다.
2. **삐져나감·잘림**: 글자·아이콘·버튼이 자기 패널 안에 있는가. 가장 긴 문구(한국어·영어·일본어·중국어)로도 들어가는가.
3. **위계와 구분**: 제목 → 본문 → 보조 정보(진행도·키 이름·버튼)가 색·크기·위치로 구분되는가.
4. **정렬과 간격**: 같은 종류의 요소가 같은 기준선에서 시작·끝나는가. 여백이 패널마다 들쭉날쭉하지 않은가.
5. **상태 표시**: 누를 수 있음/없음, 강조, 마지막 단계 같은 상태가 한눈에 구분되는가.
6. **가독성**: 글자와 배경의 대비가 충분한가. 반투명 패널 뒤 3D 장면 때문에 글자가 묻히지 않는가.
7. **화면 비율과 배치**: 1920×1080과 모바일 비율에서 배치가 유지되는가. HUD(체력·마나·스킬바·미니맵)와 기존 팝업을 가리거나 겹치지 않는가.
8. **톤 일치**: 기존 UI의 시각 언어(금속 프레임, 청록·하늘색 네온 테두리, 어두운 남색 바탕, 글꼴·굵기, 버튼 모양)와 어울리는가. 새 UI만 다른 게임처럼 보이지 않는가.
9. **문구**: 하드코딩 없이 Localization 키인가(`Docs/UI_Localization_Guide.md`), 표기가 일관된가.
