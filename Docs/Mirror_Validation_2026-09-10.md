# Mirror 추가 연결과 검증 — 2026-09-10

이 문서는 9월 9일 종료 문서 이후의 변경과 추가 검증을 기록한다. 전용 서버와 네 클라이언트는 같은 Windows PC의 서로 다른 프로세스다.

사용자의 사용량 제한에 따른 계정 변경 요청으로 작업을 중단했다. 실행 재개 순서와 마지막 수정의 검증 상태는 [중단·인계 문서](Mirror_Work_Closeout_2026-09-10.md)에 기록했다.

## 변경한 동작

- `Lobby_MirrorTest`에 WJ의 새 패시브 팝업 구성을 연결했다. 선택 → 단계 조절 → 적용, 구매 비용, 해금 유지, 초기화, 최대 단계 표시와 닫기를 기존 패시브 API로 처리한다. 준비 상태에서는 변경을 잠그고, 준비할 때 서버에 실제 구매한 패시브 상태를 전달한다.
- WJ 원본 씬은 변경하지 않았다. Mirror 로비의 준비 취소 문구가 버튼 프레임 안에 들어오도록 글자 크기와 여백을 조정했다.
- 유물 발동 시 기존 `persistedStackCount`를 갱신하고 최대 스택을 적용한다. 소유권 상실 시 버프를 제거하고 재획득 시 저장된 스택으로 복원한다.
- 인벤토리 스냅샷의 저장·복원에 스택을 포함한다. 소유 클라이언트의 스택 변경은 기존 아이템 인스턴스에 반영하여 매 발동마다 아이템이나 UI를 다시 생성하지 않는다.
- 보존된 플레이어에 새 연결을 붙일 때 이동 좌표의 수신 델타 기준값을 초기화한다. 이전 좌표에 새 좌표가 더해지던 재접속 오류를 해결하며, 기존 관전자에게 보내는 송신 기준값은 유지한다.
- 로비의 기존 EventSystem을 세션 Manager 아래에 두어 캠프로 이동하거나 재접속한 뒤에도 UI 버튼 입력을 유지한다. 로비 생성기에도 같은 배치를 적용했다.
- 기존 전투 검사에 유물, 스킬 중단, 파티 퀘스트 검증을 추가했다. 명시적인 개발 실행 인수가 있을 때만 실행한다.

## 중단 시 남은 검증

- 재접속 수정이 포함된 최신 전용 서버와 네 클라이언트에서 중단·복구 검사를 다시 실행.
- 실제 NPC 제시·리롤·수락 → 처치·아이템 획득 → 네 명의 보상 → 가방 부족 보류 → 재접속 → 공간 확보 후 한 번만 지급.
- 최신 캠프의 창·채팅 입력 차단, NPC hover, StageSelect 투표·대기·재접속 표시.

최초 사망 검사의 부활 대기는 서버의 최신 체력 스냅샷 갱신 전에 끝나는 검사 오류가 있어 대기 조건을 수정했다. 재접속 검사는 Mirror의 정상 로비 복귀가 NetworkManager에 붙어 있던 검사 실행기를 제거하여, 검사 실행기를 씬 전환 동안 유지하도록 수정했다. 이 두 원인을 게임 기능 결함으로 기록하지 않는다.

후속 실행에서는 재접속한 플레이어의 실제 서버 좌표가 `(-10, 0.08, 7)`에서 `(-20, 0.16, 14)`로 변하는 수신 델타 문제를 확인해 수정했다. NPC 검사는 네 명의 최초 제시 팝업까지 통과했고, 다음 리롤 검사에서 씬 전환 후 EventSystem이 사라진 문제를 발견했다. 별도 실제 게임 창에서도 의뢰 이름·외곽선·제시 팝업을 확인했으며, UI 입력 객체 배치 수정 뒤 버튼 흐름을 다시 검사한다.

## 유지한 경계와 남은 문제

- `DataManager.cs`, `SettingManager.cs` 원본 변경과 `WBH_PlayerEffect.cs`의 월드 폭발 연출 전달은 기존 보류를 유지한다. 실제 각 PC의 개인 저장을 위해 같은 PC의 검사 프로필 경로를 원본 Manager에 추가할 필요는 없다.
- 다음 Act에서는 런 상태와 보상 대기를 유지하고, 마지막 Act에서만 아이템을 정리하며 크레딧·패시브를 가지고 나오는 요구는 유지한다. 영구 크레딧 정산·저장 실패 복구·중복 방지의 정식 저장 연결은 미구현이다.
- 62단계 실행에서 각 클라이언트의 기존 `SciFiPitchRandomizer.Start:14` 예외 3건이 남았다. 사운드 원본과 컴포넌트는 보존했다.
- 전체 Player 빌드는 성공했지만 기존 보스 Advanced Dissolve 셰이더 오류 항목 10건을 포함했다. 후속 증분 빌드의 오류 0건을 원본 셰이더 수정으로 해석하지 않는다.
- 중단 정리 중 마지막 PlayerRemainingBuild5도 성공했다(5분 30초, 오류 항목 16·경고 82). 16개 항목은 같은 보스 Up/Leg 셰이더 문제이며 상세를 `PlayerRemainingBuild5Errors.txt`로 보존했다. 마지막 UI 수정이 포함된 실행 파일의 플레이 검증과 최신 Server 재빌드는 미완료다.
- 실제 네 대 PC, 지연·손실 주입, 성능과 전투 시각 품질의 전수 검사는 이번 자동 검사 범위 밖이다.
