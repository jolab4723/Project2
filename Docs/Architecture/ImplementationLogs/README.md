# 개인 구현 로그 운영 규칙

이 폴더는 팀원별 작업 내용과 커밋 기록을 보관한다. 여러 팀원이 같은 `DecisionLog.md`의 끝부분을 동시에 수정해 발생하는 Git 충돌을 줄이기 위해 개인 파일로 분리했다.

## 사용 방법

- 파일 이름은 `팀원이름.md` 형식을 사용한다.
- 각 팀원은 자신의 파일만 수정한다.
- 새 작업은 기존 기록을 지우거나 정렬하지 않고 문서 하단에 추가한다.
- 작업 기록 전 최신 `main`을 받은 뒤 수정하고, 기록 후 작업 코드와 함께 커밋한다.
- Codex나 Claude에 기록을 요청할 때는 팀원 이름과 작업 내용을 알려주고 본인의 구현 로그만 수정하도록 요청한다.
- `DecisionLog.md`에는 작업 내역을 복사하지 않는다. 팀이 함께 합의한 내용만 별도로 기록한다.
- 개인 구현 로그에 적힌 내용은 구현 사실을 뜻하며, 그 자체로 팀 전체가 합의한 결정이 되지는 않는다.

## 작성 양식

- 새 개인 로그는 [TEMPLATE.md](TEMPLATE.md)를 복사해 작성한다.
- 어려운 전문 용어보다 팀원이 바로 이해할 수 있는 문장을 사용한다.
- 확인되지 않은 클래스명, 파일 경로, 커밋 번호는 추측하지 않는다.

## 현재 로그

- [김성우](김성우.md)

## AI 기록 요청 예시

```text
Docs/Architecture/ImplementationLogs/TEMPLATE.md 형식을 사용해서
ImplementationLogs/김성우.md에 오늘 작업을 추가해줘.
작성자는 김성우로 표시하고, 완료한 내용과 팀에 확인할 내용을 구분해줘.
확인되지 않은 클래스명, 파일 경로, 커밋 번호는 추측하지 마.
DecisionLog.md와 다른 팀원의 로그는 수정하지 마.
```
