## 1. 다국어 표시 언어 처리 일원화 (2026-08-03 논의, 나중에 진행하기로 결론)

### 문제

현재 "현재 표시 언어"가 4곳에 흩어져 있고 설계도 서로 다르다.

| 위치 | enum | 지원 언어 | 형태 |
| --- | --- | --- | --- |
| `StatLabelDatabaseSO.currentLanguage` | 자체 `Language` | KOR/ENG | 에셋에 직렬화 |
| `ItemLabelDatabaseSO.currentLanguage` | 자체 `Language` | KOR/ENG | 에셋에 직렬화 |
| `EnemyLabelDatabaseSO.currentLanguage` | 자체 `Language` | KOR/ENG | 에셋에 직렬화 |
| `YJ_UnknownStageManager.currentLanguage` | 공용 `GameLanguage` | KOR/ENG/JPN/CHN | 컴포넌트 필드 |

- 언어를 바꾸려면 에셋 3개를 각각 열어 고쳐야 하고 런타임 전환이 안 된다.
- `Language` enum이 3벌 중복 정의되어 있고 JYJ님의 `GameLanguage`와도 별개다.
- UnknownStage 데이터는 이미 JPN/CHN까지 있는데 나머지 3개는 KOR/ENG뿐이다.

### 하기로 한 방향

- 현재 언어의 단일 소유자를 `DataManager`로 둔다(세이브 슬롯·프로필을 이미 관리하므로 설정값 소유자로 적합하고, 언어는 저장 대상이다).
- `GameLanguage`를 공용 enum으로 승격한다. 현재 `Assets/Scripts/Unknown/YJ_UnknownStageLabel.cs`(JYJ 담당)에 정의되어 있어 위치가 부적절하다.
- 라벨 SO 3종에서 `currentLanguage` 직렬화 필드를 제거하고, JYJ님 SO처럼 언어를 파라미터로 받는 형태로 통일한다. 인자 없는 오버로드가 `DataManager`의 현재 언어를 읽게 하면 기존 호출부는 그대로 두면서 런타임 전환이 된다.
- 표시 중인 UI 갱신을 위해 `OnLanguageChanged` 이벤트도 함께 넣는다.

### 진행 전 확인 필요

- `GameLanguage` enum 이동은 JYJ님 파일 수정이라 사전 공유가 필요하다.
- 라벨 SO 3종을 4개 언어로 확장할지 결정 필요. Item/Stat/Enemy 라벨 시트에는 JPN/CHN 열이 없으므로, 우선 KOR/ENG만 채우고 나머지는 KOR로 폴백하는 방식이 현실적이다.

## 2. `UnknownStageTableModel.backgroundImage` 타입 문제 (사용자 확인 대기)

- `string` → `Microsoft.Unity.VisualStudio.Editor.Image`로 바뀌어 있다(IDE가 `using`을 잘못 자동 추가한 것으로 추정).
- `ExcelSheetReader`가 지원하지 않는 타입이라 변환 시 `backgroundImage`가 **전부 `null`** 이 된다(검증 완료). 저장된 JSON에는 아직 정상값이 남아 있지만 다음 변환에서 덮어써진다.
- 엑셀 셀에는 리소스 이름 문자열만 있으므로 `string`이 맞고, 스프라이트 로딩은 이 이름으로 `Resources.Load` 하는 쪽에서 처리하는 게 맞다.
- 부수 작업: `ExcelSheetReader.ConvertValue`가 지원하지 않는 타입을 만나면 조용히 `null`을 반환하지 않고 경고를 남기도록 보강한다.

## 4. 전투 트리거 연결 (BH 담당 영역)

- `WBH_CombatManager`가 `ItemTriggerManager.Fire(TriggerCondition.OnDamageDealt / OnCrit / OnKill)`을 호출하지 않는다.
- 이 때문에 `UniqueEffect_MoveSpeedUp_OnAttack`(OnDamageDealt) 같은 발동형 고유 효과가 실제 전투에서 발동하지 않는다. `OnHitTaken`만 연결되어 있다.
