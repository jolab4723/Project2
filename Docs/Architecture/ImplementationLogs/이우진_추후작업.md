## 1. 일본어·중국어 폰트 깨짐 (2026-08-04 발견, 추후 수정)

### 증상

언어를 JPN/CHN으로 바꾸면 글자가 깨져 보인다(□ 등). 번역 데이터 문제가 아니라 **폰트 적용 문제**다.

### 원인

`YJ_LanguageManager`는 폰트를 **보관·제공만** 한다(`GetCurrentFont()`).
실제로 텍스트에 적용하는 건 `YJ_LocalizedFont` 컴포넌트이고, 이건 **TMP 텍스트 오브젝트마다 개별로 붙여야** 한다.

```
[RequireComponent(typeof(TMP_Text))]
YJ_LocalizedFont
   Start()  -> LanguageChanged 구독
   ApplyFont() -> targetText.font = languageManager.GetCurrentFont()
```

그런데 `WJ_Act1_DropTest` 씬의 `YJ_LocalizedFont` 개수가 **0개**다. 폰트를 바꿔주는 주체가 없어서
모든 텍스트가 한/영 폰트를 그대로 쓰고, 일/중 글리프가 없어 깨진다.

`YJ_LanguageManager`의 폰트 3개 필드는 2026-08-04에 연결해뒀다(Pretendard / NotoSansJP / NotoSansSC).
이건 전제 조건이라 비어 있으면 `YJ_LocalizedFont`를 붙여도 `font != null` 검사에 걸려 아무 일도 안 일어난다.

### 해결 후보

- **A. 필요한 텍스트에 `YJ_LocalizedFont`를 붙인다** — JYJ님이 의도한 정석. 다만 다국어로 표시될 TMP 텍스트마다 일일이 붙여야 한다(스탯 팝업만 해도 행 10개 × 이름/값).
- **B. 부모 아래 TMP 텍스트를 한 번에 처리하는 컴포넌트를 새로 만든다** — `Canvas_Pupop` 같은 루트에 하나만 붙여 `GetComponentsInChildren<TMP_Text>()`로 일괄 교체. 손은 덜 가지만 의도적으로 다른 폰트를 쓰는 텍스트(로고, 숫자 전용 등)까지 덮어쓰므로 예외 처리가 필요하다.
- **C. 폰트 에셋의 Fallback 설정** — 한/영 폰트의 Fallback Font Assets에 일본어·중국어 폰트를 등록하면 TMP가 글리프 없을 때 자동 대체한다. 컴포넌트를 안 붙여도 되고 기존 폰트 지정도 안 건드린다. 다만 폰트 에셋 설정 변경이라 팀 공용 자산에 영향이 간다.

**C로 전반적인 깨짐을 없애고 필요한 곳만 A를 추가하는 조합을 권장**한다.

### 진행 전 확인 필요

- 실제로 어느 화면의 텍스트가 깨지는지(스탯 팝업 / 아이템 툴팁 / 그 외).
- C를 택하면 폰트 에셋이 팀 공용이라 사전 공유가 필요하다.

## 2. `UnknownStageTableModel.backgroundImage` 타입 문제 (사용자 확인 대기)

- `string` → `Microsoft.Unity.VisualStudio.Editor.Image`로 바뀌어 있다(IDE가 `using`을 잘못 자동 추가한 것으로 추정).
- `ExcelSheetReader`가 지원하지 않는 타입이라 변환 시 `backgroundImage`가 **전부 `null`** 이 된다(검증 완료). 저장된 JSON에는 아직 정상값이 남아 있지만 다음 변환에서 덮어써진다.
- 엑셀 셀에는 리소스 이름 문자열만 있으므로 `string`이 맞고, 스프라이트 로딩은 이 이름으로 `Resources.Load` 하는 쪽에서 처리하는 게 맞다.
- 부수 작업: `ExcelSheetReader.ConvertValue`가 지원하지 않는 타입을 만나면 조용히 `null`을 반환하지 않고 경고를 남기도록 보강한다.
