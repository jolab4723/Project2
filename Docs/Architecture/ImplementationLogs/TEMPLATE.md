# 이름 구현 로그

> 담당자: 이름  
> 목적: 본인이 작업한 내용과 확인할 사항 기록  
> 주의: 이 문서는 개인 작업 기록이며, 팀 전체가 합의한 결정과는 구분한다.

## 1. 작업 기록

| 날짜 | 커밋 | 작업 내용 | 관련 시스템 | 상태 |
|---|---|---|---|---|
| YYYY-MM-DD | `커밋 번호` | 작업을 한 문장으로 요약 | 시스템 이름 | 커밋 완료 |

## 2. YYYY-MM-DD 작업 상세

### 무엇을 작업했나

- 구현하거나 수정한 기능을 쉬운 문장으로 적는다.
- 이 작업이 필요한 이유를 짧게 적는다.
- 기능이 실제로 어떻게 동작하는지 적는다.

### 주요 수정 대상

- 시스템: 확인된 시스템 이름
- 클래스: `확인된 클래스명`
- 파일: `확인된 파일 경로`
- 씬 또는 프리팹: 실제로 수정한 경우에만 기록

확인되지 않은 클래스명이나 파일 경로는 추측하지 않고 `확인 불가`로 적는다.

### 완료 확인

- [ ] 코드 작성 완료
- [ ] Unity 컴파일 확인
- [ ] 테스트 씬 또는 플레이 모드 확인
- [ ] 관련 오류와 경고 확인
- [ ] 커밋 완료

실제로 확인한 항목만 체크한다. 아직 확인하지 않은 항목은 체크하지 않는다.

### 기존 기능이 깨질 가능성

- 이 작업 때문에 영향을 받을 수 있는 기존 기능을 적는다.
- 동시에 수정하면 충돌할 수 있는 파일이나 프리팹을 적는다.
- 특별한 위험이 확인되지 않았다면 `현재 확인된 내용 없음`으로 적는다.

### 팀과 상의할 내용

- 담당자가 정해지지 않은 일
- 다른 팀원의 작업이 끝나야 진행할 수 있는 일
- 팀이 함께 정해야 하는 규칙이나 작업 순서
- 특별히 상의할 내용이 없다면 `없음`으로 적는다.

### 아직 하지 않은 일

- 이번 작업에서 제외한 기능
- 나중에 연결하거나 테스트해야 하는 기능
- 멀티플레이 적용 단계에서 처리할 내용

## 3. 기록 규칙

- 기존 작업 기록을 삭제하거나 다시 정렬하지 않는다.
- 새 작업은 문서 하단에 날짜별로 추가한다.
- 작업 사실과 팀이 합의한 내용을 구분한다.
- 제공되지 않은 클래스명, 파일 경로, 커밋 번호는 임의로 만들지 않는다.
- 상태는 `작업 중`, `구현 완료`, `확인 필요`, `커밋 완료`처럼 쉬운 표현을 사용한다.
- `DecisionLog.md`, `README.md`, 다른 팀원의 로그는 수정하지 않는다.
