## 2. 아이템 드랍 시스템 정리 (2026-07-24)

### 무엇을 작업했나

- `ItemGenerator`를 `MonoBehaviour`에서 순수 C# 클래스로 전환했다. 프리팹은 필드로 직접 들고 있지 않고, `ItemSystemController`가 생성자로 주입한다.
- `ItemSystemController`의 드랍 메서드들에서 `Quaternion rotation` 인자를 전부 제거했다. 내부적으로 `ItemGenerator.DropGeneratedItem()`을 호출할 때는 `Quaternion.identity`를 고정으로 넘긴다.
- `ItemSystemController`에 `DropGeneratedItem(ItemDefinitionSO, Vector3)` 오버로드를 추가해, 확률 롤 없이 특정 아이템을 그대로 드랍할 수 있게 했다.
- `ItemManager`의 `DropItem()`을 `DropRandomItem(EnemyGrade, Vector3)`으로 개명하고, `DropSpecificItem(ItemDefinitionSO, Vector3)`을 추가했다.
- `ItemSystemController`에 `spawnRadius`(수평 반경 랜덤 분산)와 `spawnHeightOffset`(바닥에 반쯤 묻히지 않도록 y축으로 띄우는 값, 기본 0.5)을 추가해 드랍 위치 계산에 반영했다.
- 리팩터링 도중 발견한 버그 2건을 같이 고쳤다: `ItemManager.DropSpecificItem()`이 존재하지 않는 `grade`를 참조하던 것, `ItemSystemController`의 SO 기반 오버로드가 전달받은 아이템을 무시하고 `GetRandomItemSO(grade)`로 랜덤 롤을 하던 것.
- `TestButtonController`는 곧 사용하지 않을 예정이라 `lastDropped`/`OnClickGetItem()`/`RefreshGetItemButton()`을 제거했다. 이로 인해 `Assets/SW/TEST/RandomDrop/SwTestButtonModeSwitcher.cs`가 `OnClickGetItem()`을 더 이상 찾지 못해 깨졌으며, 해당 파일은 삭제했다.
- `Assets/SW/TEST/RandomDrop/SwTestRandomDropAcquireTester.cs`에서 더 이상 존재하지 않는 `ItemDropTester`/`ItemGenerator` 관련 레거시 폴백 코드를 제거했다.
- `Assets/WJ_TestPlace/Script/Item/ItemGenerate/ItemDropTester.cs`(테스트 전용, 미사용)를 삭제했다.

## 4. 플레이어 스탯-전투 시스템 통합 (2026-07-27)

### 무엇을 작업했나

- `WJ_Act1_DropTest`(SW의 `Act1_DropTest`를 복제해온 씬)의 실제 플레이어 `Fighter`는 `T_PlayerController`/`WBH_PlayerStatus` 등 우병헌 팀원의 WBH 전투 시스템을 쓰고 있었고, WJ 스탯 시스템(`PlayerStatManager` 등)은 `WJ_StatSystemTestScene`에만 존재해 서로 연결되어 있지 않았다. `WBH_ICombatStatus`(`WBH_PlayerStatus`가 구현)가 `WBH_CombatManager`의 데미지 계산에서 플레이어·적 공용 접점으로 쓰이고 있어, `WBH_PlayerStatus` 내부 값의 출처만 WJ 스탯 시스템으로 바꾸는 어댑터 방식으로 통합했다 (사용자 확정 방향).
- `WBH_PlayerStatus.cs`(우병헌 팀원 파일, 작업 허락받음)를 수정: `MaxHealth`/`AttackPower`/`DefensePower`/`CritRate`/`CritMult`/`AttackSpeed`/`MoveSpeed`/`Fire·Ice·ElectricBonus`는 같은 GameObject의 `PlayerStatManager.Stat` 값을 반환하도록 바꾸고, 없으면 기존 Fallback 필드로 그대로 동작한다 (`Fighter`/`Gunner` 프리팹과 `TestStage`, SW `Act1_DropTest`처럼 WJ 스탯 클러스터가 없는 곳도 계속 정상 동작).
- 단위 변환 처리: WJ 스탯은 치명타 확률/치명타 피해/속성 보너스를 퍼센트 숫자(예: 5.0 = 5%)로 갖는데 `WBH_CombatManager`는 분수(0.05)·배율(1.10)을 기대해서, 그대로 넘기면 치명타율이 항상 100%가 되는 문제가 있었다. `PercentToFraction`/`PercentToMultiplier`로 변환했다.
- `TakeDamage()`/`Heal()`/`CurrentHp`/`IsDead`는 `PlayerHealthManager`로 위임하고, 기존 `OnHpChanged`/`OnDead` 이벤트는 `PlayerHealthManager`의 이벤트를 중계해서 시그니처를 그대로 유지했다.

## 34. 아이템 파이프라인에 유물(Relic) 카테고리 지원 추가 및 유물 2종 생성 (2026-08-03)

### 무엇을 작업했나

- 사용자가 `ItemDataTable.xlsx`의 `RelicDefinitions` 시트를 채운 뒤, 유물 2종 데이터를 WJ 영역에 생성하고 WJ/SW 양쪽 아이템 DB에 등록해달라고 요청했다.
- 파이프라인을 돌려보니 **유물이 JSON에 하나도 안 나왔다.** 확인해보니 `RelicDefinitions` 시트가 원래 비어 있어서 변환기가 `// 아직 빈 시트`로 명시적으로 건너뛰고 있었고, 임포터에도 `CreateOrUpdateRelicDefinitions`가 TODO 스텁으로만 있었다. 그래서 유물 지원을 먼저 구현했다.
  - `ItemDataTableModel.cs`: `RelicDefinitionRow` 클래스와 `relicDefinitions` 목록 추가. 유물은 메인/서브 옵션 없이 보유만으로 효과가 적용되는 카테고리라 스탯 컬럼이 없고 시트 구조가 포션과 동일해서 같은 형태로 만들었다.
  - `ItemDataTableExcelToJson.cs`: `RelicDefinitions` 시트 처리 케이스 추가, 로그에 Relic 개수 포함.
  - `ItemDataTableSOImporter.cs`: `CreateOrUpdateRelicDefinitions`를 포션과 같은 패턴으로 구현(스탯 인자는 비워서 전달).
- 작업 전에 엑셀의 `uniqueEffectId`가 `UE_MassProducedCore`인데 실제 에셋명은 `UE_MassCore`라 서로 어긋나는 것을 발견해 사용자에게 확인했고, **`UE_MassProducedCore`로 통일**하기로 해서 에셋을 리네임했다(GUID 유지). 영문 표시명 `Mass-Produced Core`와 맞추기 위함이다.
- 파이프라인이 4단계로 나뉘어 있는데(1.JSON → 2.SO생성 → 3.아이콘 → 4.고유효과 연결) 처음에 2단계까지만 돌려서 고유 효과 참조가 `NULL`이었다. 4단계까지 실행해서 연결을 완료했다.
