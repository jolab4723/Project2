## 2. 아이템 드랍 시스템 정리 (2026-07-24)

### 무엇을 작업했나

- `ItemGenerator`를 `MonoBehaviour`에서 순수 C# 클래스로 전환했다. 프리팹은 필드로 직접 들고 있지 않고, `ItemSystemController`가 생성자로 주입한다.
- `ItemSystemController`의 드랍 메서드들에서 `Quaternion rotation` 인자를 전부 제거했다. 내부적으로 `ItemGenerator.DropGeneratedItem()`을 호출할 때는 `Quaternion.identity`를 고정으로 넘긴다.
- `ItemSystemController`에 `DropGeneratedItem(ItemDefinitionSO, Vector3)` 오버로드를 추가해, 확률 롤 없이 특정 아이템을 그대로 드랍할 수 있게 했다.
- `ItemManager`의 `DropItem()`을 `DropRandomItem(EnemyGrade, Vector3)`으로 개명하고, `DropSpecificItem(ItemDefinitionSO, Vector3)`을 추가했다.
- `ItemSystemController`에 `spawnRadius`(수평 반경 랜덤 분산)와 `spawnHeightOffset`(바닥에 반쯤 묻히지 않도록 y축으로 띄우는 값, 기본 0.5)을 추가해 드랍 위치 계산에 반영했다.
- 리팩터링 도중 발견한 버그 2건을 같이 고쳤다: `ItemManager.DropSpecificItem()`이 존재하지 않는 `grade`를 참조하던 것, `ItemSystemController`의 SO 기반 오버로드가 전달받은 아이템을 무시하고 `GetRandomItemSO(grade)`로 랜덤 롤을 하던 것.
- `TestButtonController`는 곧 사용하지 않을 예정이라 `lastDropped`/`OnClickGetItem()`/`RefreshGetItemButton()`을 제거했다. 이로 인해 `Assets/SW/TEST/RandomDrop/SwTestButtonModeSwitcher.cs`가 `OnClickGetItem()`을 더 이상 찾지 못해 깨졌으며, 해당 파일은 삭제했다.
- `Assets/SW/TEST/RandomDrop/SwTestRandomDropAcquireTester.cs`에서 더 이상 존재하지 않는 `ItemDropTester`/`ItemGenerator` 관련 레거시 폴백 코드를 제거했다.
- `Assets/WJ_TestPlace/Script/Item/ItemGenerate/ItemDropTester.cs`(테스트 전용, 미사용)를 삭제했다.

### 기존 기능이 깨질 가능성

- `ItemGenerator`가 더 이상 `MonoBehaviour`가 아니므로, 씬이나 프리팹에 남아 있던 기존 `ItemGenerator` 컴포넌트 참조는 Missing Script로 표시된다. `WJ_StatSystemTestScene`은 직접 정리했지만, `Assets/SW/Prefabs/StatTestPrefeb_copy.prefab`과 `Assets/Scenes/Maps/Act1_Maps/Act1_Camp/Act1_Camp.unity`, `Assets/SW/Scenes/Act1_DropTest.unity`는 같은 참조가 남아 있을 수 있다(팀원 소유 파일이라 직접 정리하지 않음).
- `Assets/SW/TEST/RandomDrop/SwTestButtonModeSwitcher.cs`는 `TestButtonController.OnClickGetItem()` 삭제로 컴파일이 깨져서 파일 자체를 삭제했다(김성우 확인 후 진행).

### 팀과 상의할 내용

- `WJ_Act1_DropTest.unity`에 `YJ_HUD` 프리팹 인스턴스가 있는데, 원본 프리팹 에셋(`guid: 23b851051e60ccf4d9cd5b435427ff10`)이 현재 프로젝트에 없어서 씬을 열 때마다 Missing Prefab 경고가 발생한다. 원본 에셋 확인이 필요하다.
- `ItemSystemController`의 `DropGeneratedItem(EnemyGrade, Vector3)` / `DropGeneratedItem(ItemDefinitionSO, Vector3)` 오버로드를 `ItemManager`처럼 `DropRandomItem`/`DropSpecificItem`으로 개명할지는 아직 정하지 않았다.

### 아직 하지 않은 일

- 실제 적 사망 처리 코드에서 `ItemManager.Instance.DropRandomItem(...)` 호출 연결은 이번 작업에서 하지 않았다.
- `spawnRadius`(1f), `spawnHeightOffset`(0.5f) 기본값은 실제 레벨 스케일에 맞춘 튜닝을 거치지 않은 값이다.

## 3. `ItemDropTableSO` Excel→JSON→SO 파이프라인 구축 (2026-07-24)

### 무엇을 작업했나

- 기존 `DataSystem.ItemTableSOImporter`(스탯풀), `DataSystem.ItemDataTableSOImporter`(아이템 데이터)와 동일한 구조로, `ItemDropTableSO`(적 등급별 드랍 확률/희귀도 가중치/아이템 종류 가중치) 전용 Excel→JSON→SO 변환기를 새로 만들었다.
- `Assets/SW/Scripts/WorldItem/DropRules/ItemDropTableSO.cs`(김성우 제작)는 `enemyDropRules`/`itemKindWeights`가 private 필드라 해당 파일은 수정하지 않고, 임포터에서 `SerializedObject`/`SerializedProperty`로 직접 값을 써넣는 방식을 사용했다.
- 엑셀 시트 3개(`EnemyDropRules`, `RarityWeights`, `ItemKindWeights`)는 `ExcelSheetReader.MapRows<T>`의 리플렉션 매핑 규칙에 맞춰 헤더 이름을 각 Row 클래스의 필드명과 정확히 일치시켰다.
- `Assets/WJ_TestPlace/Script/Item/Data/ItemData/ItemDropTable.asset`의 기존 실제 값(등급별 드랍 확률, 희귀도 가중치, 아이템 종류 가중치)을 그대로 엑셀에 옮겨 넣었다.
