## 2. 최종 기획 원칙

### 2.1 이번의 '액티브함'은 새 단축키가 아니라 행동의 결과다

현재 기본 공격·회피·기존 스킬 운용에 **파동, 국소 폭발, 열 방출, 공간 재생, 표식 소비**를 붙인다. 별도 장비 액티브 슬롯, 입력 키, 조작 UI, 스킬 장착 시스템은 이번에 만들지 않는다. 자동 발동이더라도 위치·거리·공격 순서·회피 타이밍을 선택하게 만들면 단순 스탯 증가와 다른 경험을 줄 수 있다.

신규 수치 보너스를 기존 임시 스탯 위에 덧붙이지 않는다. 완성한 아이템은 임시 고유효과를 교체한다. 검증하지 못한 아이템은 현재 효과를 유지한다. 툴팁만 미래 기믹으로 바꾸는 중간 상태는 출시하지 않는다.

### 2.2 역할을 겹치지 않게 나눈다

- **Fighter:** 공허의 수확자는 처치 각도, 폐열 절단 대검은 공격 리듬, 수호자의 정의는 반격 생존, 초냉매는 동일 표적 제어를 담당한다.
- **Gunner:** 스타 브리처는 근거리 위험 보상, 반물질 랜스는 직선 정렬, 일식 기관은 지역 점유, 에코 챔버는 과거 위치 설계, 스마일 시그널은 협동 집중 사격을 담당한다.
- **방어구·유물:** 무기의 행동을 도와야 한다. 모든 장비에 독립 광역 폭발을 붙이지 않으며, 유물의 인벤토리 점유·중복 제한·성장·지원 역할을 유지한다.

기존 등급 원칙을 이어받아 큰 전장 변화는 전설 무기에, 유일 신발은 회피 뒤의 조건부 공격 강화에 둔다. 새로운 아이템·등급 승격·세트 보너스는 이번 전환의 필수 작업이 아니다. [S2]

### 2.3 마감 기준의 채택선

| 완료선 | 새로 완성할 효과 | 의미 |
|---|---|---|
| **A: 최소 완성본 3종** | 공허의 수확자, 스타 브리처, 폐열 절단 대검 | 사용자가 원하는 대표 무기를 살리고, 처치·근거리·축열의 서로 다른 장면을 확보한다. |

## 4. 출시용 개별 동작 명세

**이 절의 숫자는 모두 최초 조정용 제안값이다.** '공격력의 X%'는 기존 피해 공식을 통과하는 계수이며 최종 HP 감소량 X%를 보장한다는 의미가 아니다. 명시하지 않은 새 추가 피해는 비치명 `DamageCause.Effect`이고, 직접 공격·치명 발동형 장비 효과를 다시 발동하지 않는다. 상태이상 틱은 기존 `DoT` 경로를 따른다. 기존 무기의 일반 타격과 이펙트는 보존한다.

### A1. 공허의 수확자 — 공간 절단

**플레이 경험:** 앞줄의 약한 적을 베어 뒷줄까지 가르는 낫. 플레이어 주위에 원형 폭발이 생기는 무기가 아니라, **어느 적을 어느 방향으로 마무리하느냐**가 중요한 무기다.

| 항목 | 최종 제안 |
|---|---|
| 발동 | 이 무기의 유효한 Fighter 기본 직접 공격으로 적 처치를 확정했을 때 |
| 시작점·방향 | 사망 적의 피격 직전 위치에서, 해당 기본 공격에 저장된 수평 공격 방향으로 진행 |
| 판정 | 길이 6m·전체 폭 2m의 전방 통로, 살아 있는 적 최대 6개체, 각 1회 |
| 피해·제한 | 공격력 60%의 무속성 Effect, 비치명. 공격 번호당 파동 1회, 소유자 기준 쿨다운 1초 |
| 다중 처치 | 같은 공격으로 여러 적을 처치하면 서버가 최초 확정한 적 하나만 시작점으로 사용 |
| 벽·단차 | 막힌 벽 너머로 통과하지 않음. 다른 층의 적은 높이·장애물 검사로 제외 |
| 연쇄 제한 | 파동으로 발생한 Effect 처치, 화상 DoT 처치, 스킬 처치는 새 파동을 만들지 않음 |

위치와 방향은 **피해 적용 전에 값으로 보존**한다. 사망·풀 반환 뒤 적 Transform을 따라가거나, 다음 프레임의 플레이어 방향으로 바꾸면 안 된다. 새 Void 속성을 추가하지 않고 무속성 피해에 보라색 공간 절단 표현을 사용한다.

첫 구현은 지연 이동체가 아니라 **같은 피해 처리 구간에서 전방 통로를 한 번 판정하는 순간 절단**으로 한다. 보라색 절단 궤적도 같은 구간을 즉시 보여준다. 실제로 날아가며 맞는 투사체처럼 연출하고 피해는 먼저 주는 불일치는 피한다. 나중에 이동 파동으로 바꾸려면 별도 수명·이동 충돌 작업으로 다룬다.

파동의 처치는 기존 보상 경로로 정확히 한 번 정산한다. 고철 압축기 등 원래 처치 보상형 효과는 기존 규칙대로 받을 수 있지만, 공격형 처치 전파는 재발동시키지 않는다. 파동은 보스 단독전에서 발동하지 않는 **잡몹 정리 특화**를 받아들인다. 보스용 추가타나 즉사 판정을 억지로 덧붙이지 않는다.

- 툴팁 초안: **기본 공격으로 적을 처치하면 그 위치에서 전방 6m를 가르는 공간 파동을 방출하여 공격력의 60% 피해를 줍니다. 최대 6명. 쿨타임 1초. 파동은 다시 파동을 일으키지 않습니다.**
- 전용 검수: 한 번에 5마리 처치해도 파동 1개, 파동으로 6마리 처치해도 추가 파동 0개, 사망 적 풀 반환 후에도 위치·방향 불변, 벽 뒤 피해 0, 일반 보상 중복 0.

### A2. 스타 브리처 — 제련로 개방

**플레이 경험:** 안전하게 멀리서 쏘는 대신 적에게 접근했을 때 탄착점이 터지는 근접 사격 무기다.

기본 산탄의 실제 공격 원점에서 **3m 이내**의 적에게 유효한 Direct 피해를 주면, 최초로 확정한 근거리 적의 피격 위치에서 반경 **2.5m**, 공격력 **35%**의 화염 폭발을 1회 발생시킨다. 폭발은 최대 5개체, 쿨다운 1.2초다. 직접타로 시작 표적이 죽어도 그 위치의 폭발은 발생하며, 죽은 시작 표적에는 피해를 다시 주지 않는다. 살아 있는 직접 대상이 폭발 범위 안에 있다면 기본타와 폭발을 각각 받을 수 있다.

거리는 플레이어의 이후 위치가 아니라 **해당 공격 원점과 실제 적중 지점**으로 계산한다. 산탄 한 번이 여러 Collider·표적에 맞아도 폭발은 하나다. 이 조건을 만족한다고 Fighter 근접 공격으로 분류하지 않는다. 별도의 산탄 펠릿 시스템을 만들지 않고 현재 산탄 범위 공격에 연결한다. 화염색 폭발과 별개로 추가 Burn을 이 효과에서 중복 예약하지 않는다.

- 툴팁 초안: **3m 안의 적을 기본 공격으로 맞히면 탄착점에 작은 폭발을 일으켜 주변 적에게 공격력의 35% 화염 피해를 줍니다. 쿨타임 1.2초.**
- 전용 검수: 거리 2.99/3.01m, 여러 근거리 표적·Collider, 시작 표적 즉사, 원거리 사격, 공격 후 이동, 벽·단차, 인페르노 등 Fighter 전용 효과 미발동.

### A3. 폐열 절단 대검 — 폐열 방출

**플레이 경험:** 가벼운 연속 타격으로 온도를 올린 다음 강한 한 번을 원하는 방향에 쓰는 무기다. 라이트세이버의 지속 공격속도 스택과 구분한다.

서로 다른 기본 공격이 유효하게 적중할 때마다 열 1을 얻어 **4까지 충전**한다. 열 4를 만드는 공격에서 곧바로 방출하지 않고, **그 다음 유효 기본 공격**에 전방 길이 4m·전체 각도 70도의 열 방출을 더한다. 방출은 최대 4개체에 공격력 **50%** 화염 Effect를 주고 열을 모두 소비한다. 하나의 기본 공격이 8마리를 맞혀도 열은 1만 얻는다.

열은 5초간 유효 기본 적중이 없으면 사라진다. 빗나감·스킬·Effect·DoT는 열을 얻거나 소비하지 않는다. 무기 교체·사망·씬 이동에서 초기화한다. 방출 자체의 추가 Burn은 별도로 붙이지 않는다. 기존 공격의 속성 상태 부여는 유지한다. 자기 피해·과열 폭발·별도 열 게이지 창은 넣지 않는다.

- 표시: 기존 버프 아이콘의 0~4 스택과 충전 완료 시 칼날의 짧은 발광. 숫자와 별개로 다음 타격이 준비됐음을 보인다.
- 툴팁 초안: **기본 공격을 4회 적중시키면 열을 충전합니다. 다음 기본 공격이 전방에 공격력의 50% 화염 피해를 추가로 방출합니다. 5초간 적중하지 않으면 열이 사라집니다.**
- 전용 검수: 4번째 공격과 5번째 공격 구분, 한 번의 광역 공격으로 4충전 금지, Effect 재충전 금지, 방출 중 처치 버프가 생겨도 같은 방출의 능력치 불변.

### B1. 일식 기관 — 잔류 일식

**플레이 경험:** 적이 서 있거나 지나갈 장소를 불태운다. 중력 우물은 감속, 특이점 박격포는 기다린 뒤 폭발, 일식 기관은 지속 점유다.

기본 유탄이 충돌한 위치에 반경 **3m**, 지속 **4초**의 화염 지대를 남긴다. 0.5초마다 살아 있는 범위 내 적에게 **기존 Burn1**을 적용·갱신한다. 장판의 즉시 추가 폭발이나 별도의 중복 지속 피해는 넣지 않는다. Burn1의 피해 공식·강도는 기존 값을 사용하며 이 문서에서 임의로 상향하지 않는다. 이탈 후에는 마지막으로 적용된 Burn의 남은 수명만 진행된다.

소유자당 장판은 **최대 2개**, 초과 시 가장 오래된 장판을 제거한다. 같은 적의 Collider 중복과 동일 소유자 장판 중첩으로 화상 개수가 증가하지 않는다. 서로 다른 플레이어가 화상을 갱신했을 때는 **기존 Burn이 실제로 보유하는 출처**를 따른다. 소유자별 독립 Burn 중첩 시스템을 새로 만들지 않는다. 무기 교체 후 장판 유지, 소유자 사망·씬 이동·새 런에서 생성 장판 취소를 적용한다.

- 표시: 저명도 바닥 테두리와 중심 잔불. 범위를 가리는 큰 불기둥을 반복하지 않는다.
- 전용 검수: 진입·이탈·재진입, 겹친 장판에서 틱 폭증 없음, 서로 다른 소유자의 출처·처치 귀속, 기존 중력/특이점의 동시 개수 제한을 침범하지 않음.
- 선행 조건: §6.3의 효과 종류별 수명 분리. 여러 시전자의 Burn 갱신 규칙이 원래 P4 계약과 다르면 그 문제를 먼저 기록·해결하고 이 아이템을 완료 처리하지 않는다.

### B2. 크루세이더 — 심판 연쇄

실제 Fighter 기본 직접 공격의 **치명타 적중**에서만 첫 추가 대상에게 공격력 **50%**, 두 번째에게 **35%**의 전기 연쇄 피해를 준다. 탐색 반경 4m, 최대 추가 대상 2개, 쿨다운 1.5초다. 아크 블레이드의 벽 검사·방문 대상 제외·직접 대상 집합 제외를 재사용한다. 연쇄 추가타 자체는 비치명이며 치명타 효과를 다시 발동하지 않는다.

추가 대상이 없으면 쿨다운을 소비하지 않는다. 공격 번호당 실제 치명타 결과가 확인된 첫 적중을 발동 기회로 삼는다. 같은 공격의 첫 비치명 대상 때문에 이후 치명 대상까지 무조건 차단하지 않도록 치명 조건 검사와 중복 기록의 순서를 정한다.

아크는 꾸준한 분산 공격, 크루세이더는 치명 옵션을 모았을 때의 간헐적 강한 연쇄다. 기존 치명 확률 +12%와 치명 피해 +25%는 제거하고, 치명 확률은 기본 능력치·옵션·다른 장비에서 조달한다. 치명 확률이 낮은 빌드에서 발동이 적은 것은 의도된 선택 비용이다.

- 전용 검수: 치명 0%/100%, 같은 AttackId의 비치명·치명 혼합, 단일 보스, 직접 대상 중복 제외, 다른 플레이어의 동일 무기 쿨다운 분리.

### B3. 수호자의 정의 — 응보 방벽

적에게 맞아 **실제 HP가 줄었을 때** 그 손실량의 50%를 방벽 에너지로 저장한다. 저장량 상한은 최대 HP의 12%, 저장 수명은 최초 피격으로부터 5초다. 추가 피격은 저장량만 더하고 무한히 만료 시각을 연장하지 않는다. 다음 유효 Fighter 기본 적중에서 저장량만큼의 보호막을 만들고 저장량을 비운다. 보호막 유지 5초, 발동 뒤 쿨다운 8초이며 쿨다운 중에는 새 에너지를 모으지 않는다.

회피·무적·피해 0·이미 있는 보호막이 전부 흡수한 피격·자기 비용은 충전하지 않는다. 저장 중 사망하면 부활용 보호막으로 이월하지 않는다. 태양의 은혜와 달리 '잘 피해서 얻는 보호막'이 아니라 '살아남아 반격해서 얻는 보호막'이다.

보호막을 합산하는 새 체계는 만들지 않는다. **하나의 활성 장비 보호막**에서 더 큰 잔량의 새 보호막만 교체 적용하고, 작거나 같은 값은 덧붙이거나 시간을 연장하지 않는다. 새 보호막이 채택되면 출처 아이템과 만료 시각도 교체하며, 이전 출처의 해제 콜백이 새 보호막을 지우지 않아야 한다. 더 강한 보호막 때문에 이번 지급이 무효여도 저장량·발동 기회는 소비한다. 이 정책은 구현 제안이며 기존 태양의 은혜와 함께 회귀 검사가 필요하다.

- 전용 검수: 실제 HP 손실과 요청 피해량 구분, 치명적 피격, HP 상한 변경, 보호막 교체·만료·장착 해제, 태양의 은혜와 동시 착용.

### B4. 닌자의 움직임 — 그림자 보법

서버가 승인한 회피 뒤 **3초 안의 다음 기본 공격**에 피해 +20%를 준비한다. 쿨다운 6초, 중첩하지 않는다. Fighter와 Gunner가 모두 사용한다. 이번 신발은 명확한 짧은 공격 기회이므로 **유효한 기본 공격 실행이 승인되는 시점에 해당 AttackId에 보너스를 예약하고 준비를 소비**한다. 공격이 빗나가도 되돌려주지 않는다. 거절된 입력·스킬 입력은 소비하지 않는다.

따라서 밤의 칼날의 '다음 유효 적중까지 보존'과 신발의 '3초 내 다음 공격 실행'은 소비 시점이 다르다. 두 효과가 같은 Fighter 공격에 붙으면 +40%와 +20%를 합산하여 해당 준비 계수는 **1.60배**로 한다. 1.4 × 1.2로 곱하지 않는다. 일반 공격 보너스 등 다른 기존 계산 계층은 바꾸지 않는다.

산탄과 근접의 같은 AttackId에 속한 직접 대상 모두에 예약된 계수를 적용한다. 라이플은 발사 시 예약 정보를 탄에 보존하고 적중 시 다시 준비를 소비하지 않는다. 새 준비 상태는 장비 교체·사망·씬 이동에서 없애며, 이미 발사된 탄의 예약은 무기 발사 자격과 같은 수명 정책으로 처리하되 소유자 사망 후 새 효과 피해는 허용하지 않는다.

- 현재 코드의 `TryGetPreparedAttackEffect`는 **Fighter 무기 슬롯 전용**이다. 신발 SO만 교체하면 된다고 판단하지 않는다. 공격 실행 승인과 발사 스냅샷의 좁은 연결이 추가로 필요하다. [S7]
- 전용 검수: Fighter 빗나감 소비, Gunner 탄 비행 중 3초 만료·회피 재사용·무기 교체, 산탄 다중 표적, 밤의 칼날 단독 회귀와 합산 1.60배.

### C1. 반물질 랜스 — 장갑 종단

기본 라이플 탄이 서로 다른 적 **최대 3개체**를 실제로 통과한다. 첫 적은 기존 기본 직접 피해, 두 번째는 원래 공격 계수의 70%, 세 번째는 50%를 받는다. 후속 관통 피해는 별도 Direct 이벤트를 반복하지 않는 Effect로 처리한다. 첫 타의 치명 결과는 기존 규칙을 유지하고 후속타는 비치명이다.

같은 탄·같은 적은 여러 Collider를 지나도 한 번만 맞는다. 벽·지형에서는 멈추고, 남은 사거리·수명은 기존 탄의 것을 사용한다. 관통한 적의 피격 VFX와 실제 탄의 진행을 일치시킨다. 단순 `penetrationFlat` 증가나 첫 적 뒤에 피해만 뿌리는 광역 공격을 '실제 관통 완료'로 취급하지 않는다.

발사할 때 효과 자격을 보존하고 각 적에 도달할 때 기존 피해 진입 규칙으로 능력치를 읽는다. 첫 적의 피해를 그대로 복사하지 않으며, 적마다 방어·저항을 적용한다. 무기 교체 후에도 그 탄의 관통 자격은 남고 소유자 사망 후 추가 피해는 취소한다.

- 선행 작업: 기존 라이플 투사체의 충돌·소멸·풀 반환 경계 검토. 일반 라이플과 유리빛 궤도에 관통이 새지 않도록 좁게 분기한다.
- 전용 검수: 일렬 4마리 중 3마리만 피해, 한 적의 겹친 Collider, 고속 탄, 벽, 사거리 종료, 관통 중 교체·사망·풀 재사용.

### C2. 에코 챔버 — 잔향 사격

기본 산탄 사격이 서버에서 승인되면 그 공격의 **원점·수평 방향·실제 사거리·부채꼴 각도·무기 효과 자격**을 기록한다. **0.45초 뒤** 같은 위치와 방향으로 한 번 더 판정하며 공격력 **35%**, 최대 6개체의 비치명 Effect 피해를 준다. 예약 쿨다운 1.5초, 소유자당 예약 상한 2개다. 빈 공간에 쏜 공격도 기록되지만 원본 사격 이후 새로 범위에 들어온 적은 재생 시 맞을 수 있다.

현재 캐릭터 위치로 새 공격을 쏘거나, 원본에서 맞았던 대상 목록에 피해를 다시 넣는 것으로 대체하지 않는다. 재생 순간의 살아 있는 적을 **원래 공간**에서 다시 찾고 벽·단차를 검사한다. 현재 프로젝트의 산탄은 범위 공격이므로 새 펠릿 시스템을 만들지 않는다. 파란 잔상 총구/부채꼴이 과거 위치에서 한 번 보이면 충분하다.

능력치는 재생 시작 시 한 번 읽어 그 재생 전체에 사용한다. 무기 교체 후 이미 예약한 잔향은 남으며, 소유자 사망·비활성화·씬 이동·새 런에서 취소한다. 잔향은 잔향을 예약하지 않고 기본 공격 충전도 올리지 않는다.

- 전용 검수: 사격 후 플레이어 이동·회전, 원래 표적 이탈·새 적 진입, 예약 뒤 무기 해제, 사망·씬 이동, 재생 한 번·연쇄 재생 0회.

### C3. 월드 엔더 — 종말 포격

**8초마다 준비되는 특수 탄두**를 다음 서버 승인 기본 유탄 발사에 싣는다. 그 발사에서 준비를 소비하고 재충전 시간을 시작한다. 첫 충돌에서 기존 유탄 피해에 더해 반경 **5m**, 최대 8개체에 공격력 **150%**의 무속성 Effect 폭발을 한 번 준다. 공중 소멸 등으로 충돌하지 못하면 준비를 환불하지 않는다.

특이점 박격포처럼 2초 뒤 다시 터지는 무기가 아니라 **충전된 그 한 발의 충돌이 강한 무기**다. 평상시 유탄 전부를 대형 폭발로 바꾸지 않는다. 발사 후에는 특수 탄두 자격을 보존하지만 소유자 사망·씬 이동에는 추가 폭발을 취소한다. 교체 후 재장착으로 8초 준비를 초기화해 연사할 수 없어야 한다.

- 표시: 충전 아이콘과 발사 전 탄두 발광, 발사된 특수 탄은 비행 외형으로 구별. 큰 연출도 한 번의 실제 피해 범위만 보여준다.
- 전용 검수: 같은 프레임 연속 발사에서 특수 탄 1개, 땅 충돌, 다중 Collider, 기본 폭발과 추가 폭발 각각 1회, 미충돌 소멸, 재장착 쿨다운 악용.

### C4. 코어 브레이커 — 코어 노출

같은 적에게 **3초 안에 서로 다른 기본 공격을 3회** 적중시키면 그 적의 방어력을 **4초 동안 20% 감소**시킨다. 새로운 세 공격으로 갱신할 수 있지만 약화 자체는 중첩하지 않는다. 같은 소유자의 다른 대상 적중은 자신의 연속 카운트를 새 대상으로 옮긴다. 스킬·다중 Collider·추가타는 횟수를 올리지 않는다.

효과는 공격자의 관통 스탯이 아니라 **적에게 남는 약화**이므로 아군도 그 적을 공격할 때 이득을 얻는다. 이미 약화된 적에게 다른 코어 브레이커 사용자가 적용해도 감소율은 합산하지 않고 같은 약화의 수명만 갱신한다. 방어력은 음수로 만들지 않는다. 보스에는 기본 제안으로 10%만 적용하되, 실제 보스의 면역·저항 정의가 있으면 그 정의를 우선한다.

- 선행 작업: 적 방어 계산·상태 소유권을 담당하는 팀원과 약화 진입점을 합의해야 한다. `penetrationFlat`을 올리는 임시 우회는 최종 구현이 아니다.
- 전용 검수: 아군 피해 변화, 서로 다른 시전자, 3초 경계, 대상 풀 반환, 보스·면역, 원래 방어력 복구.

### C5. 초냉매 — 열 강탈

같은 적에게 3초 안에 **서로 다른 기본 공격 3회**를 적중시켜 냉각을 축적한다. 각 유효 적중은 1초의 15% 둔화를 갱신하고, 3번째에는 **0.6초 빙결**을 시도하며 냉각을 비운다. 같은 적은 빙결 발동 뒤 **5초 동안 다시 빙결 준비를 받지 않는다**. 이 제한은 여러 초냉매 사용자가 돌려가며 공격해도 공유한다.

보스에게는 빙결로 공격 패턴을 끊지 않는다. 기본 제안은 1초의 15% 둔화만 남기는 것이며, 둔화에도 면역이면 아무 제어 효과를 주지 않는다. '빙결 면역이므로 더 강한 다른 제어를 보장'하는 우회는 넣지 않는다. 실제 일반 적 빙결 수신과 보스 내성 경로를 검증한 후 연결한다.

- 표시: 표적에 작게 보이는 냉각 단계와 성공한 빙결만 표시. 면역 표적에 얼어붙은 것처럼 연출하지 않는다.
- 전용 검수: 4인 무한 빙결 방지, 대상 변경·시간 만료, 효과타 미충전, 보스 패턴 지속, 면역·저항 및 풀 복구.

### C6. 와일드파이어 — 되살아나는 불씨

이 무기로 적용한 **자신의 화상이 유효한 적**을 자신의 기본 직접 공격 또는 해당 화상 DoT로 처치했을 때, 사망 위치 4m 안의 살아 있는 적 **최대 3개체**에게 기존 Burn1을 옮긴다. 소유자 쿨다운 1초, 처치 1회당 전파 1회다. 다른 플레이어가 적용한 화상이나 다른 무기 출처의 화상은 자격이 없다.

전파된 화상은 **1세대**이고 그 화상으로 다시 전파하지 않는다. 한 적에게 현재 유지되는 Burn의 실제 출처와 세대를 기준으로 판단한다. 단순히 마지막 프레임에 '불이 붙어 있었다'는 bool만 저장해서는 안 된다. 기존 직접 공격으로 새로 적법하게 적용한 0세대 화상과 전파된 1세대 화상을 구별한다.

화상 피해·보상 계산은 기존 P4 경로를 사용하고, 별도 화상 틱 루프를 겹쳐 만들지 않는다. 무기 교체는 이미 적용된 Burn 자체를 임의 삭제하지 않지만, **교체 후 새 불씨 전파 자격은 없앤다**. 소유자 사망·씬 이동에서 전파 상태를 정리한다. 불씨 이동 표현은 실제로 화상을 받은 대상에만 연결한다.

- 선행 작업: Burn 출처에 아이템/효과 자격과 전파 세대를 추적할 수 있어야 한다. 현재 일반 `OnKill` 사건만으로 구현하지 않는다.
- 전용 검수: 내 화상/남의 화상/다른 무기 화상, 0→1세대만 허용, 한 번에 여러 처치, 무기 교체, 풀 재사용, 사망·드롭·경험치 중복 0.

### C7. 스마일 시그널 — 동기화 표식

라이플 기본 직접 적중으로 살아남은 적에게 **3초 표식**을 남긴다. 다른 살아 있는 아군의 다음 기본 Direct 적중이 표식을 소비하여 **소비자 공격력 25%**의 비치명 Effect 피해를 추가한다. 추가 피해와 그 처치 보상의 공격자는 소비자로 한다. 시전자는 표식을 제공하며 별도 중복 처치 보상을 만들지 않는다.

한 적에는 이 종류의 표식 하나만 유지한다. 기존 표식이 남아 있으면 다른 시전자가 소유권이나 시간을 빼앗지 않는다. 시전자당 동시에 3개 표적까지 유지하고, 초과 시 자신의 가장 오래된 표식부터 없앤다. 같은 적에는 소비 후 1초의 재표식 제한을 둔다. 서로 다른 두 아군이 동시에 맞혀도 서버에서 소비권을 먼저 차지한 하나만 추가 피해를 받는다.

싱글 또는 다른 살아 있는 전투 참가자가 없는 상황에서는 시전자 본인이 **서로 다른 다음 AttackId**로 소비할 수 있다. 같은 공격이 생성 즉시 소비해서는 안 된다. 기존 표식 소비를 먼저 처리하고 같은 적중에서 바로 새 표식을 만들지 않는다. 표식 시전자 사망·장착 해제·씬 이동 또는 표적 사망·풀 반환 시 표식을 제거한다.

- 표시: 적 위 작은 지원 표식, 소비 시 한 번의 연결 섬광. 단순 주변 공격력 오라로 대체하지 않는다.
- 전용 검수: 생성자/소비자 분리, 두 아군 동시 소비, 생성 공격 즉시 소비 금지, 싱글 자가 소비, 4인 같은 무기, 죽은 시전자·재접속·표적 풀링.

## 5. 기존 방어구·유물과 만드는 빌드

새 아이템이나 세트 보너스를 만들지 않고 현재 존재하는 장비의 역할을 활용한다. 무기는 동시에 하나만 장착한다. 아래 서로 다른 무기 두 개가 한 플레이어에게 동시에 발동하는 조합을 전제하지 않는다.

| 플레이 방향 | 실제 조합 예시 | 선택의 의미 |
|---|---|---|
| 잡몹 수확 | 공허의 수확자 + 폐기된 부스터 모듈 + 고철 압축기 | 적열의 측면으로 움직여 파동을 내고 처치 성장 효과를 활용한다. 보스 단독전 약점은 남는다. |
| 축열 공격 | 폐열 절단 대검 + 절전모드 헤드셋 + 오버클럭 코어 | 기본 공격 리듬과 스킬 자원을 함께 운용한다. 오버클럭의 체력 손해는 그대로 감수한다. |
| 위험한 근거리 사격 | 스타 브리처 + 닌자의 움직임 + 태양의 은혜 | 회피 후 접근 사격과 무피격 유지가 충돌하는 긴장감을 만든다. 보호막을 상시 보장하지 않는다. |
| 안전한 지역 관리 | 일식 기관 + 마나 중계기 | 고정 화염 구역에 스킬을 겹치고 아군 자원을 돕는다. 이동 중인 단일 적에 무조건 강한 빌드는 아니다. |
| 반격 생존 | 수호자의 정의 + 절전모드 헤드셋 + 마나 중계기 | 실제 피격 후 반격으로 버틴다. 태양의 은혜와의 보호막 합산을 빌드의 핵심으로 삼지 않는다. |
| 협동 집중 사격 | 스마일 시그널 사용자 + 별도 Fighter/Gunner 동료 | 서로 다른 플레이어가 표식 생성과 소비를 나눠 맡는다. 파티 조합이지 1인의 무기 중복 장착이 아니다. |

공격속도·치명·마나·체력의 단순 보너스도 유효한 빌드 재료다. 신규 희귀 13종을 전설 수준의 기믹으로 전부 바꾸지 않는다. 오버클럭 코어의 교환 조건, 고철 압축기의 기존 아이템 저장 스택, 마나 중계기의 지원 오라는 보존한다. 기존 H1~H4/C1~C4/B2~B4/R1~R6 아이디어를 새 장비 18개 추가 요구로 확대하지 않는다. 특히 C2형 무피격 보호막은 태양의 은혜, C3형 피격 전환은 수호자의 정의에 통합하여 중복 제작을 피한다. [S1][S3]

## 6. 실제 코드 대조에서 드러난 구현 선행 조건

### 6.1 공허의 수확자: 일반 OnKill에는 필요한 정보가 부족하다

현재 네트워크 적은 보상 수령자에게 `ItemTriggers.Fire(TriggerCondition.OnKill)`을 호출한다. 이 호출만으로는 새 파동에 필요한 피해 종류·원본 공격 번호·아이템 출처·처치 위치·공격 방향을 전달할 수 없다. [S10]

첫 작업에서는 **기본 공격의 확정된 생존→사망 전이**를 공통 피해 경로에서 한 번 잡고 필요한 값만 전달한다. 기존 `WBH_DamageRequest`/`WBH_DamageResult`에 이미 있는 값은 재사용하고, 없는 출처·위치·방향만 작은 기록으로 보완한다. 같은 사망을 공통 Resolver와 네트워크 적의 이벤트 양쪽에서 각각 발행하면 안 된다. 싱글과 멀티가 같은 조건을 통과하도록 한다.

후속 파동 피해는 활성 피해 처리 구간에서는 기존 FIFO에 넣는다. 사망 콜백 안에서 `TryProcessPlayerDamage`를 재귀 호출하면 현재 Resolver가 재진입을 거절한다. OnKill 전역 이벤트를 재설계하는 대형 작업보다, 먼저 공허의 수확자가 요구하는 좁은 경계를 완성한다. DoT 출처 전파는 C6에서 별도 추가한다. [S7][S8]

**착수 조사에서 확인한 구체 경계:** `PlayerDamageResolver.ExecuteDamageInternal`의 `target.TakeDamage(result)` 전후가 공통 전이 관찰 후보이며, 피해 적용 전에 표적 위치와 공격 출처를 값으로 확보해야 한다. 네트워크 적은 `TakeDamage` 내부에서 `FireDamageDealt`와 사망/보상을 이미 발행하므로 파동 통지·보상을 양쪽에 중복 추가하지 않는다. `WBH_DamageRequest`/`Result`에는 Cause·AttackId·HitPosition·HitEffectDirection이 이미 있어 BH 공용 타입 확장은 먼저 필요성을 입증한다.

`PlayerCombatAuthority.ResolveServerAttack`이 전달하는 `HitEffectDirection`은 **`transform.position - hitPosition`**, 즉 피격 연출용 역방향이다. 이것을 파동의 진행 방향으로 그대로 쓰거나 부호만 바꿔 공격 forward와 같다고 가정하지 않는다. 싱글/서버의 실제 기본 공격 경계에서 같은 AttackId의 수평 공격 방향을 한 번 보존하고, 표적 사망 후 현재 Transform을 다시 읽지 않는 연결을 A1에서 구현한다.

### 6.2 Effect라고 해서 자동으로 비치명이 되는 것은 아니다

현재 `EnqueueFollowUpDamage`는 `canCrit`를 받지만, 지연 효과가 쓰는 공개 `TryProcessPlayerDamage`에는 같은 인자가 없고 내부 기본값은 치명 허용이다. 따라서 새 효과에서 **`DamageCause.Effect`만 지정하고 비치명 구현이 끝났다고 판단하면 안 된다.** [S8][S9]

새 비동기 효과가 실제 필요해질 때 기존 Resolver에 명시적 치명 정책을 전달하는 좁은 확장을 한다. 기존 호출의 기본 동작을 바꾸지 않는다. 치명 확률 100%의 플레이어로 새 Effect가 실제 비치명인지 검사한다. 기존 특이점 박격포의 동작을 이번 기획만으로 몰래 바꾸지 않는다.

동기 후속타는 기존 직접 피해 진입 스냅샷을 쓴다. 새 지연 재생·독립 광역 실행은 **실행 시작 시점의 능력치를 한 번 읽어 같은 실행의 모든 대상에 공유**한다. 첫 대상 처치로 고철 압축기 스택이 올라갔다고 같은 폭발의 두 번째 대상부터 더 강해지지 않게 한다. 다음 화상 틱이나 다음 공격은 다시 능력치를 읽을 수 있다. 기존 동기 FIFO를 다음 프레임 예약기로 사용하지 않는다.

현재 `ToAttackType`은 Effect/DoT를 기본적으로 Normal 계산 경로에 연결한다. '발동형 기본 공격 효과를 다시 일으키지 않음'과 '일반 공격 피해 스탯의 영향을 받지 않음'은 다르다. 별도의 Effect 전용 새 피해 공식을 만들지 않고 기존 공식을 적용한 결과로 계수를 조정한다. [S8]

### 6.3 장판 종류가 늘어나면 현재 bool 분류를 그대로 쓸 수 없다

현재 `PlayerGrenadeEffect.Initialize`는 중력 우물과 특이점 박격포 두 타입만 받는다. `PlayerItemEffectState.RegisterGrenadeEffect`는 `IsGravity`가 같은 객체끼리 상한을 계산한다. 따라서 일식 기관·월드 엔더를 단순히 '중력이 아닌 효과'로 추가하면 기존 특이점 예약을 잘못 취소할 수 있다. [S7][S9]

B1에서 처음 필요해질 때 종류별 상한을 명시적으로 구분한다. 작은 효과 종류 구분 또는 실제 SO 타입을 사용하면 충분하며, 전역 장판 Manager·Factory·범용 스케줄러를 새로 만들 필요는 없다. 공통 수명은 재사용하되, 효과마다 필요 없는 옵션 수십 개를 한 클래스에 넣지 않는다.

### 6.4 '한 번 공격'과 '한 번 피해'는 다르다

현재 일반 Triggered 버프는 피해 이벤트에 반응한다. 열 4충전, 근거리 폭발, 준비 공격, 빙결 카운트를 이 이벤트에 그대로 붙이면 산탄이나 광역 기본 공격의 대상 수만큼 충전될 수 있다. 새 카운트는 **플레이어 + 발동 출처 + 유효 AttackId**로 공격당 한 번만 증가시킨다. 대상별 약화/빙결에는 대상의 생애 식별도 포함한다. [S7]

현재 동기 후속 피해 중복 키는 `(AttackId, DamageCause, Target)`다. A에서 한 무기 효과만 추가하는데 불필요하게 전체 키 체계를 갈아엎지 않는다. C7처럼 서로 다른 효과 생산자의 추가 피해가 같은 공격·대상에 실제로 공존할 때만 효과 종류/실행 번호를 함께 구분한다. 후속타를 통과시키려고 AttackId를 0으로 보내거나 임의 난수로 바꾸지 않는다. [S8]

현재 `resolutionStates`와 `SourceSnapshot`은 **`TryProcessPlayerDamage` 한 번과 그 FIFO** 동안 유지되고 `finally`에서 제거된다. 같은 광역 기본 공격의 다음 직접 표적은 별도 호출이다. 따라서 A1~A3의 공격당 발동 기록은 이 큐의 중복 키만으로 해결되지 않으며 플레이어의 공격 수명 안에 유지해야 한다. 하나의 파동/폭발/방출 안의 모든 후속 대상은 그 발동을 시작한 피해 경계의 동일 스냅샷을 사용한다.

착수 시 A2의 서버 산탄은 `gunnerFirePoint` 원점으로 범위를 찾지만 요청의 적중점은 `ClosestPoint(transform.position)`으로 만들었다. A2 구현은 싱글·서버 모두 실제 발사 원점에서 얻은 적중점과 직접 대상 전체를 피해 전에 보존한다. 실제 Gunner 싱글 검사에서 Direct 콜백 중 공격자가 20m 이동하고 시작 표적이 즉사해도 저장한 발사 원점·적중점으로 폭발하는 것을 확인했다. 서버/원격 동일성은 A3 이후 검증한다.

### 6.5 새로운 적 상태는 기존 내성·해제 경로를 따라야 한다

냉각·방어 약화·불씨 전파는 개인 스탯 버프와 다르다. 상태 출처, 중복 갱신, 보스 내성, 죽음·풀 반환, 관찰자 표시를 같은 계약으로 묶어야 한다. 기존 상태 Controller를 우회한 별도 HP 차감, 임의 NavMeshAgent 이동, 클라이언트 Freeze 판정을 추가하지 않는다.

중력 우물의 실제 흡인, 보스 강제 이동, 전파의 무제한 세대, 전설 효과의 무제한 누적, 별도 장비 액티브 입력은 마감 범위 밖으로 고정한다.

## 8. 데이터 전환: 기존 아이템은 그대로, 효과만 안전하게 교체

### 8.1 새 효과 ID를 사용하는 이유

현재 임시 효과는 Passive/Triggered/Threshold 타입이다. 생성기의 기존 타입 불일치 차단을 해제하거나 `.asset`의 스크립트 GUID만 바꿔 최종 클래스로 만드는 방식을 사용하지 않는다. **새 타입이 필요한 최종 효과에는 새 효과 ID를 만들고, 기존 itemId의 연결만 교체**한다. 아이템 자체의 ID·GUID·외형·아이콘·강화 데이터는 유지한다. [S12]

### 8.2 1종씩 완료하는 순서

착수 조사에서 `ItemDataTableSOImporter.InsertUniqueEffects`가 **효과 생성 실패 후에도 기존 SO 연결을 계속 시도**하며 전체 `SaveAssets`를 호출하는 것을 확인했다. 아래 연결 단계를 실행하기 전에 실패 중단·이전 참조 일관성·다른 Dirty 에셋 보존을 검증하고 필요한 좁은 수정을 승인받는다. 효과 SO 생성기의 타입 차단이 아이템 통합 메뉴 전체의 안전성을 보장한다고 가정하지 않는다. 상세 계획 §13.4를 따른다.

1. 해당 기존 아이템·임시 SO·설명·연결 GUID와 관련 수치의 기준 상태를 기록한다.
2. 공통 코드의 실제 필요한 진입점과 작은 효과 설정 타입을 구현한다. 다른 효과에 필요한 것까지 미리 만드는 범용 프레임워크 작업은 하지 않는다.
3. Excel 원본의 효과 표·라벨에 새 ID/타입/계수를 추가하고 승인된 변환기에 해당 타입의 검사를 연결한다. JSON이나 생성 SO만 손으로 고쳐 끝내지 않는다.
4. 효과 SO와 아이콘·4개 언어 설명을 먼저 생성·검증한다. 기존 임시 SO의 타입과 GUID는 그대로 둔다.
5. 같은 아이템의 `uniqueEffectId`를 새 ID로 바꾸고 아이템 연결 단계를 다시 실행한다. 이 시점부터 임시 스탯 보너스는 빠져야 한다.
6. 동일 아이템을 저장·복원·거래·재장착하여 새 효과 하나만 적용되는지 확인한다. 타입 오류나 데이터 변환 실패를 이전 JSON으로 숨기지 않는다.
7. 두 번 재생성해 결과가 동일한지 확인한다. 실패하면 해당 아이템의 연결을 기존 ID로 되돌리고 라벨도 실제 임시 효과와 일치시킨다.

과거 임시 SO는 참조가 0인지 확인하기 전까지 지우지 않는다. 전환 중 남겨 둔 구형 효과는 표에서 '롤백 보존/현재 미사용'으로 표시하여 사용 중인 효과와 구분한다. 정리 작업은 전환 검증 뒤에 하고, 테스트 효과 삭제 이력을 이유로 이름이 비슷한 자산을 일괄 제거하지 않는다.

새 효과의 수치와 툴팁 자리표시자는 같은 데이터에서 나온다. 번역 4개 언어의 피해%, 초, m, 대상 수, 소수점, 스택 수를 함께 검사한다. 기존 UI가 새 쿨다운 타입을 자동 지원한다고 가정하지 않는다. 현재 `GetRemainingCooldown`은 Triggered/Chain 분기 중심이므로 새 표시 경로를 확인해야 한다. [S7][S12]

### 10.2 실제 플레이 검수 순서

**1단계:** Editor에서 실제 Fighter/Gunner와 실제 적을 사용해 단일 효과를 확인한다. enum 값이나 카운터만 강제로 바꾼 테스트는 실제 발동 검증의 대체물이 아니다.

**2단계:** 싱글, Host + 원격 클라이언트 1명, 같은 무기를 든 두 플레이어를 순서대로 확인한다. Host 자신의 화면만 보지 말고 원격 공격자와 관찰자 화면을 포함한다.

**3단계:** Windows 또는 실제 배포 대상의 전용 서버에서 4인 혼합/동일 빌드, Act1/Act2의 대표 전투·보스·캠프 왕복·새 런을 확인한다. Linux 배포가 목표라면 해당 서버에서 같은 항목을 확인하고 Windows 결과로 대체하지 않는다.

**4단계:** 가능한 실제 지연 환경에서 소비권·쿨다운·지속 상태를 확인한다. 한 PC의 loopback 4인 결과와 LAN/WAN 결과는 따로 적는다. 기존 구현 로그의 PASS를 새 14종의 PASS로 복사하지 않는다.

### 10.3 성능은 측정값과 상한으로 관리한다

파동은 소유자당 초당 최대 1회, 스타 브리처는 1.2초당 1회, 일식은 소유자당 장판 2개, 잔향은 예약 2개, 표식은 시전자당 3개라는 명세 상한을 검증한다. 4인 동시 사용에서는 개인 상한을 합친 최악 조건을 만든다. 기존 중력 장판·특이점 예약과 합쳐 테스트하며 서로의 상한을 잘못 공유하지 않는지도 확인한다.

같은 장면·적 수·난수 조건에서 적용 전/후 서버 프레임 시간, 클라이언트 프레임 시간, GC 할당, 활성 효과 수, 네트워크 전송량을 비교 기록한다. 아직 측정하지 않은 FPS나 ms 수치를 문서에 성공 결과처럼 넣지 않는다. 전역 전수 검색을 매 프레임 반복하지 않고 기존 표적 탐색·풀·표시 경로를 우선 사용한다.

### 10.4 완료의 정의

**코드 존재 → 데이터 연결 → 실제 발동 → 소유권/수명 회귀 → 관찰자 표시 → 재생성·툴팁 → 출시 대상 플레이 검수**까지 확인한 아이템만 최종 효과 완료로 표시한다. 애니메이션·VFX만 있고 판정이 없거나, 판정만 있고 설명·관찰자 표시가 틀린 아이템은 완료가 아니다.

## 11. 마감 전에 같이 확인할 기존 데이터

새 효과와 별도로 현재 표에는 `UE_CyberneticCore`의 회피 후 **이동속도 고정값 +77**, 4초, 쿨다운 30초가 남아 있다. 이것이 의도된 최종 수치인지 먼저 확인한다. 퍼센트 +77이 아니므로 이동·회피·카메라·네트워크 보정에서 체감이 크게 달라질 수 있다. 이 문서에서는 임의로 값을 변경하지 않는다. [S3]

반대로 `UE_AdvancedCore`는 현재 최대 체력 +20의 Passive로 변경되어 있다. 과거 문서의 HELLO WORLD 시험 효과가 아직 그대로라고 적으면 안 된다. `UE_HelloWorldBeacon`의 반경 12 설정과 테스트 효과 삭제도 9월 23일 변경 이력을 기준으로 구분한다. `UE_MassProducedCore`의 'OnDamageDealt 미연결' 같은 오래된 note는 현재 공통 트리거 코드와 대조해 정리한다. [S3][S5][S7]

이런 기존 설명·시험 수치 정리는 필요하지만, 새 전설 기믹 14종 구현에 섞어 한 번에 대규모 밸런스 패치를 하지 않는다. 변경 목적과 검증 결과를 나눠 남긴다.

### 12.2 각 효과의 작업 순서

1. 해당 단계의 명세·기준 GUID·변경 후보·담당자 승인 범위를 확인한다.
2. 싱글/서버 공통 진입점과 최소 설정 타입을 구현한다. 필요한 경계 검사부터 Assets 밖 `run_script`에 구성한다.
3. 원본 표·변환기·SO·실제 아이템·아이콘·4개 언어 설명을 §8의 순서로 연결한다. 기존 타입 차단과 GUID를 보존한다.
4. 실제 Fighter/Gunner·적에서 전용 조건과 기존 효과 회귀를 검사하고 소유자/관찰자 표시를 확인한다. 싱글, Host, 원격, 다인 검증 결과를 각각 적는다.
5. 재생성 2회, Console 신규 오류, 범위 밖 Diff, 코드 수정 규약을 확인한다. 미통과 항목이 있으면 완료 처리하지 않는다.
6. 검증된 구현만 개인 로그에 추가하고 위 표의 해당 행을 갱신한다. 다음 효과의 미리 구현이나 미검증 데이터 전환은 섞지 않는다.

남은 기능을 다음 AI에게 넘길 때는 이 문서의 해당 아이템 번호, 기준/변경 커밋, 실제 변경 파일, 실행한 시험, 미검증 항목을 함께 전달한다. 구현 사실은 김성우 개인 구현 로그에 기록하고, 제안만 완료 로그로 옮기지 않는다. 이 문서를 기준으로 진행 상태를 갱신하며 회차별 유사 계획서를 계속 만들지 않는다.

**최종 선택은 '모든 장비에 복잡한 능력'이 아니라 '눈에 보이는 대표 무기 몇 개 + 그 무기를 받쳐주는 이해하기 쉬운 장비'다. 공허의 수확자의 처치 파동은 반드시 살리고, 위험한 기능은 기믹을 가짜 스탯 효과로 바꾸는 대신 뒤 순서에 둔다.**
