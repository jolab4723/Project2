김관영 UI 담당 전달사항 - 캠프/통합 테스트 UI 정식 연결
작성일: 2026-07-31
문서 상태: 팀 검토 및 정식 UI 통합용

1. 목적

현재 Act1_Camp_Test 씬에서는 스탯, 인벤토리, 상점, 강화, Pause, Settings를 한 씬에서 검증하기 위해
SW의 CampTestSidePopupRouter가 입력과 일부 팝업 전환을 임시로 담당하고 있습니다.

이 라우터는 테스트를 계속하기 위한 임시 연결이며, 실제 캠프 씬과 전투 씬에서는
김관영 담당의 UI 입력 및 팝업 관리 구조가 같은 역할을 맡아야 합니다.


2. 현재 테스트 씬의 임시 구성

대상 씬
- Assets/SW/Scenes/Act1_Camp_Test.unity

임시 입력 및 팝업 연결
- Assets/SW/Scripts/Testing/CampTestSidePopupRouter.cs
- I: 인벤토리 요청
- L: 스탯 팝업 요청
- K: 스킬 팝업 요청
- J: 퀘스트 팝업 요청
- ESC: 현재 열린 창 닫기 또는 Pause 팝업 열기

인벤토리 계열 창 상태 확인
- Assets/SW/Scripts/Inventory/UI/InventoryPartView.cs
- HasOpenWindow 프로퍼티로 인벤토리, 상점, 강화 중 열린 창이 있는지 확인

Pause 및 Settings 재사용 방식
- 기존 KY_PopupManager의 Show/Hide와 팝업 스택을 그대로 사용합니다.
- 테스트 씬의 PopupManager GameObject는 활성화되어 있습니다.
- KY_PopupManager 컴포넌트는 비활성화되어 이벤트를 중복 구독하지 않습니다.
- Awake에서 Instance와 팝업 목록만 준비한 뒤, 임시 라우터가 Show/Hide를 호출합니다.
- Canvas_Pupop에는 KY_SettingsManager가 추가되어 있습니다.

이 구성은 테스트 전용입니다. 정식 UI 관리자가 현재 인벤토리 구조를 지원하면 제거해야 합니다.


3. 현재 확인된 UI 연결 문제와 원인

3-1. I/L 단축키가 작동하지 않았던 문제

관련 파일
- Assets/Scripts/UI/Test/KY_UIInputManager.cs

확인된 원인
- GameInputActions를 Awake에서만 생성했습니다.
- OnDisable에서는 입력을 Disable하지만 OnEnable에서는 다시 Enable하지 않습니다.
- 씬 복사, 오브젝트 재활성화, Enter Play Mode 설정에 따라 inputActions가 null인 상태로
  Update가 실행되어 NullReferenceException이 반복될 수 있습니다.

최소 수정 방향
- OnEnable에서 inputActions가 없으면 생성합니다.
- OnEnable마다 Enable합니다.
- OnDisable에서 Disable합니다.
- OnDestroy에서 Dispose합니다.

정식 통합 시 추가 검토
- KY_UIInputManager, KY_RebindManager, KY_ShortcutView 등이 각각 new GameInputActions()를 만들고 있습니다.
- 리바인딩한 키와 실제 게임 입력이 서로 다른 인스턴스에 적용되지 않도록
  UI 입력과 리바인딩이 같은 입력 인스턴스를 사용해야 합니다.
- 씬마다 실제 UI 입력을 감지하는 소유자는 하나만 두는 것이 안전합니다.


3-2. 스탯 이름이 전부 HP로 보였던 문제

관련 파일
- Assets/Scripts/UI/Popup/Status/KY_StatusPopup.cs
- Assets/Scripts/UI/Popup/Status/KY_StatRow.cs

확인된 원인
- KY_StatusPopup.statLabels 참조가 비어 있었습니다.
- 10개 KY_StatRow.nameText 참조가 모두 비어 있었습니다.
- 각 스탯 값 연결은 정상이었지만 이름을 바꿀 텍스트 참조가 없어 기본값 HP가 남았습니다.

필수 씬/프리팹 연결
- statLabels: Assets/WJ_TestPlace/Data/Player/StatLabelDatabase.asset
- hpRow부터 penetrationRow까지 각 KY_StatRow.nameText를 해당 행의 Text (TMP)에 연결

현재 Act1_Camp_Test 씬에는 위 참조가 복구되어 있습니다.


3-3. 세부 스탯 표시 중 장비 교체 시 텍스트가 겹치는 문제

관련 파일
- Assets/Scripts/UI/Popup/Status/KY_StatusPopup.cs
- HandleStatChanged
- OnDetailToggleChanged
- RebuildLayout

확인된 원인
- 세부 보기 토글을 바꿀 때는 RebuildLayout을 호출합니다.
- 장비 교체로 OnStatChanged가 발생할 때는 RequestData와 SetData만 실행하고
  RebuildLayout을 호출하지 않습니다.
- 텍스트 값은 바뀌지만 레이아웃이 이전 크기로 남아 겹칩니다.

최소 수정 방향
- HandleStatChanged에서 RequestData 호출 후, 세부 보기 상태라면 RebuildLayout을 호출합니다.
- 필요하면 RebuildLayout 안에서 Canvas.ForceUpdateCanvases 호출 후
  LayoutRebuilder.ForceRebuildLayoutImmediate를 실행합니다.
- 장비 변경 한 번에 스탯 이벤트가 여러 번 발생한다면 중복 레이아웃 코루틴만 하나로 제한합니다.


3-4. 아무 창도 없을 때 ESC가 아무 동작도 하지 않았던 문제

정식 KY_PopupManager의 기존 정책
- 일반 팝업이 있으면 가장 위 팝업 닫기
- 사이드 팝업이 있으면 해당 팝업 닫기
- 아무것도 없으면 PopupType.Pause 열기

현재 통합에 필요한 ESC 우선순위
1) Settings가 열려 있으면 Settings 닫기
2) Pause가 열려 있으면 Pause 닫고 Time.timeScale 복구
3) 인벤토리, 상점, 강화가 열려 있으면 해당 창 닫기
4) 스탯, 스킬, 퀘스트가 열려 있으면 해당 창 닫기
5) 아무 창도 없으면 Pause 열기

주의 사항
- InventoryPartView와 팝업 관리자가 ESC를 각각 독립적으로 판단하면
  인벤토리를 닫는 동시에 Pause가 열릴 수 있습니다.
- ESC 우선순위 판단은 정식 팝업 관리자 한곳에서 담당하는 것이 좋습니다.


4. 권장 책임 분리

김관영 UI 시스템
- GameInputActions의 UI 단축키 감지
- KY_GameEvents 요청 발행
- 팝업 열기, 닫기, 전환 순서 관리
- ESC 우선순위 관리
- 키 리바인딩과 단축키 표시 갱신

김성우 인벤토리/상점/강화 시스템
- 인벤토리, 상점, 강화의 실제 상태와 규칙 처리
- InventoryPartView가 제공하는 열기/닫기 기능
- 아이템 이동, 구매, 판매, 강화 결과 처리

이우진 스탯 시스템
- 실제 스탯 데이터 소유 및 계산
- 장비, 버프, 패시브 반영 후 OnStatChanged 발행

중요 경계
- UI 관리자가 인벤토리나 스탯 데이터를 직접 소유하지 않습니다.
- UI 관리자는 요청과 화면 전환을 담당합니다.
- InventoryPartView와 KY_StatusPopup은 각 담당 시스템의 결과를 표시합니다.


5. 정식 KY UI 통합 작업 제안

5-1. KY_UIInputManager 수명주기 보강
- OnEnable에서 입력 생성 및 Enable
- OnDisable에서 Disable
- OnDestroy에서 Dispose
- null 상태로 Update가 실행되지 않도록 처리

5-2. 입력 인스턴스 공유 방식 결정
- 실제 입력 감지와 리바인딩이 같은 GameInputActions 인스턴스를 사용하도록 정리
- 새 전역 Singleton을 추가하기보다 기존 UI 입력 소유자에서 제공하는 방식을 우선 검토
- Mirror 연동 전에는 로컬 플레이어별 입력 소유권으로 옮길 수 있는 구조인지 확인

5-3. KY_PopupManager에서 현재 인벤토리 구조 지원
- 구형 InventiryPopup 직접 제어 제거 또는 테스트용으로 격리
- 현재 InventoryPartView를 통해 인벤토리, 상점, 강화 창 상태 확인 및 닫기
- 스탯, 스킬, 퀘스트 사이드 팝업과 인벤토리 계열 팝업의 우선순위 통합
- Pause/Settings 팝업 스택은 기존 Show/Hide 구조 재사용 가능

5-4. 스탯 팝업 연결 보강
- StatLabelDatabaseSO 및 각 nameText 참조를 정식 UI 프리팹에 저장
- 장비/버프/패시브 변경 시 세부 보기 레이아웃 재계산
- 팝업을 껐다 켜야만 정상화되는 흐름이 남지 않도록 확인

5-5. 씬별 구성
- 캠프 씬: 인벤토리, 상점, 강화, 스탯, 스킬, 퀘스트, Pause, Settings
- 전투 씬: 인벤토리, 스탯, 스킬, 퀘스트, Pause, Settings
- 상점과 강화가 없는 씬에서도 PopupManager가 null 참조를 내지 않도록 선택 참조로 처리
- 씬마다 KY_UIInputManager 또는 정식 대체 입력 소유자는 하나만 배치


6. 정식 통합 후 제거할 임시 요소

- Assets/SW/Scripts/Testing/CampTestSidePopupRouter.cs
- Act1_Camp_Test의 CampTestSidePopupRouter 컴포넌트
- 비활성 KY_PopupManager를 Instance/Show/Hide 용도로만 사용하는 테스트 구성
- 임시 라우터에 연결된 pausePopup, popupManager, inventoryPartView 참조

InventoryPartView.HasOpenWindow는 정식 팝업 관리자가 인벤토리 계열 창 상태를 확인할 때
그대로 재사용할 수 있으므로 제거할 필요가 없습니다.


7. 완료 확인 항목

- I를 누르면 현재 인벤토리 UI가 한 번만 열린다.
- L, K, J를 누르면 각각 스탯, 스킬, 퀘스트 팝업이 한 번만 열린다.
- 아무 창도 없을 때 ESC를 누르면 Pause가 열린다.
- Pause에서 설정 버튼을 누르면 Settings가 열린다.
- Settings에서 ESC를 누르면 Settings만 닫히고 Pause는 유지된다.
- Pause에서 ESC 또는 계속하기를 누르면 Pause가 닫히고 Time.timeScale이 1로 돌아온다.
- 인벤토리가 열린 상태에서 ESC를 누르면 인벤토리만 닫히고 Pause는 열리지 않는다.
- 스탯 등 사이드 팝업이 열린 상태에서 ESC를 누르면 해당 팝업만 닫힌다.
- 리바인딩한 키가 실제 입력과 HUD 단축키 표시에 함께 반영된다.
- 스탯 이름이 각 항목에 맞게 표시된다.
- 세부 스탯 보기 중 장비 교체를 해도 텍스트가 겹치지 않는다.
- 플레이 모드 진입, 종료 및 UI 비활성화 후 재활성화 시 입력 예외가 없다.


8. 팀에서 확인할 사항

- 정식 UI 입력 인스턴스를 어느 컴포넌트가 소유할지
- KY_PopupManager가 InventoryPartView를 직접 참조할지, 요청용 API를 둘지
- 캠프와 전투 씬의 팝업 목록 차이를 Inspector 설정으로 처리할지
- 현재 구형 InventiryPopup을 제거할지 테스트 UI로 격리할지

위 항목은 제안이며 팀에서 아직 확정하지 않은 결정입니다.
