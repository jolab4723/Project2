## 1. 목적과 진행 원칙

고유효과는 장비 이름에 어울리는 행동과 선택을 만든다. 무기는 공격·표적 선택, 투구는 행동 순서·자원 관리, 상의는 생존·피격 대응, 부츠는 이동 리듬, 유물은 가방 공간을 사용하는 빌드 변화를 맡는다.

아이템 등급은 효과 복잡도와 전투 영향에 맞춘다. **유일(Unique)은 밤의 칼날을 기준으로 자신의 스탯 변화, 조건부 강화, 다음 공격 계수처럼 수치 중심 효과를 우선한다.** 장판·연쇄·관통·공격 재생·상태 전파·아군 소비 표식처럼 전장 규칙이나 공격 흐름을 크게 바꾸는 무기 효과는 전설(Legendary)에 둔다. 이 기준에 따라 아크 블레이드, 수호자의 정의, 폐열 절단 대검, 와일드파이어, 초냉매, 코어 브레이커, 중력 우물, 반물질 랜스, 스마일 시그널, 에코 챔버를 전설로 승격했다. 특이점 박격포를 비롯해 이미 전설인 같은 계열 무기는 유지한다. 유물은 이번 등급 조정 대상에서 제외한다.

빌드 단위는 **무기 1개 + 실제 장착 가능한 방어구 + 소지 유물 + 기존 스킬**이다. 무기 두 개를 동시에 장착한 것처럼 시너지를 계산하지 않는다. 같은 유물 여러 개의 효과는 기본적으로 중첩하지 않는다. 각 효과는 강한 상황, 약한 상황, 조건이나 공간 비용을 함께 정한다.

기존 PlayerContext·Stat·Buff·상태이상·인벤토리·풀·Mirror 권한 경로를 재사용한다. 실제 첫 효과에 필요한 기능부터 만들고, 범용 Manager·Factory·스케줄러를 미리 추가하지 않는다. 피해·생명주기·서버 권한을 줄여서 코드를 간결하게 만들지는 않는다.

고유효과 코드도 Mirror 통합 코드와 같은 작성 규칙을 적용한다. 변경 지점에는 `SW 수정`을 표시하고, 변경한 메서드의 XML `<summary>`에는 발동 조건·대상·싱글/멀티 권한과 결과를 쉬운 말로 적는다. 공개 API는 플레이어 참조 연결, 공통 규칙 실행, StageSelect 외부 제어에 필요한 범위로 제한한다. 기존 요청·결과 타입과 이벤트를 먼저 재사용하며, 효과 하나를 위한 인터페이스·Factory·Manager를 추가하지 않는다. 메서드·변수·직렬화 필드는 주변 코드의 이름과 어휘를 따르고 기존 공개 호출 계약과 직렬화 필드명은 가능한 유지한다.

사용자 지시에 따라 `$ponytail full`과 코드·주석 지침을 이후에도 별도 명시 없이 준수한다. 기존 API·Unity 기능·설치 패키지를 확인한 뒤 최소 변경을 선택하며, 기존 팀원 주석·입력 검증·피해/권한/수명 처리·검증을 생략하지 않는다. 스킬 자체와 기존 코드 수정 규약은 보존한다. 다른 담당 스크립트는 파일과 이유를 제시하고 `이 스크립트를 수정할까요?`에 대한 승인을 받은 뒤 수정한다.

## 3. 현재 데이터 현황

2026-09-30 조사에서 전환 대상 14종의 JSON 연결과 Unity에 로드된 실제 아이템 SO를 대조했다. **14/14가 기존 Passive/Triggered/Threshold 효과를 참조하며 아이콘도 연결되어 있다.** '공란 장비 16종' 상태로 되돌려 설명하지 않는다. 과거 2026-09-22의 효과 60행/연결 아이템 56개는 그 시점의 기록이다.

- 현재 원본/JSON은 아이템 **164개**(무기 102 / 방어구 41 / 소비품 5 / 유물 16), 효과 **89개**, 효과 연결 아이템 **85개**다. A1/A2/A3의 기존 Passive/Triggered SO를 보존하며 새 파동·폭발·폐열 SO를 추가했다. 효과 라벨은 언어별 89개다. 상세 근거는 상세 계획 §13에 기록한다. 연결 수는 실제 발동·실플레이·다인 완료 수가 아니다.
- 기존 대표 10종은 §2의 완료 이력을 보존하고 새 변경 후 회귀한다. 신규 14종은 A1/A2/A3 코드·데이터 **3/14 구현**, 최종 완료 판정은 **0/14**다.
- `UE_AdvancedCore`는 현재 최대 HP +20 Passive다. 과거 HELLO WORLD 상태와 구분한다. `UE_CyberneticCore`의 이동속도 Flat +77/4초/30초는 별도 밸런스 확인 대상으로 유지한다.
- 옛 테스트 효과 정리 이력을 신규 자산 삭제 근거로 쓰지 않는다. 전환할 임시 SO도 실제 참조·롤백 필요가 끝나기 전에는 삭제하지 않는다.
- Common/Advanced 공란이나 나머지 Rare 장비를 모두 신규 행동형 효과 제작 대상으로 확대하지 않는다.

## 6. 남은 실행 순서

## 7. 최종 검수까지 남은 범위

- 여러 PC의 LAN/WAN·지연/손실 환경과 전체 경로 검수. 서버와 별도 Player 4개의 동일·혼합 빌드, 관찰자 수신, 재접속·새 런은 Q1에서 통과했다.
- 보스 전체 패턴 중 상태이상, 정식 Act1 웨이브와 최종 성능. Q1 보스 시험은 실제 보스 씬에서 AI를 정지한 상태의 저항·면역 검사다.
- 공격속도 변화의 Fighter 타이밍, 저프레임·원격·공격 중 속도 변경. Gunner 복귀 블렌드는 측정했지만 임의 조정하지 않았다.
- 9월 22일 기록의 엘리베이터 앵커 오류와 Full Boss Pipeline의 CampStatusPopup.fireRow 참조 오류는 통합 검수 전에 현재 재현 여부를 확인한다. 이번 문서 조사에서 재현하거나 해결했다고 판정하지 않았다.
- 새 전환 14종 및 나머지 표 기반 효과의 실제 동작·다인 검수를 일괄 완료로 표시하지 않는다. 신규 후보의 제작과 최종 성능 검수는 미수행이다.

## 8. 문서 유지 방법

전체 계획서는 완료 이력·장비 목록, 상세 계획서는 해당 파트의 파일 연결·코드 규약·실행 절차, 최종 전환 계획서는 신규 14종 명세·진행 상태를 갱신한다. 리뷰에서 새 결함이 나오면 해당 파트의 남은 작업에 넣고 회차별 새 인계 문서를 만들지 않는다. A1/A2/A3의 구현·실행 검증·미실행 검증은 김성우 개인 구현 로그 332/333/335번에 구분해 기록한다. 기존 기록과 DecisionLog는 보존한다.
