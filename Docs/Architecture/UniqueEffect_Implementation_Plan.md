# 고유효과 전체 계획서

- 기준일: 2026-09-20

- 다음 작업: **P5-A 보호막 1종 → P5-B 다음 공격 준비 효과 1종 → P6 장판·지연 효과**. D1 데이터 재생성과 Q1 서버·별도 Player 4개 검수는 완료했다.
- 구현 규칙·파트별 작업·시험 방법: [고유효과 상세 계획서](UniqueEffect_Detailed_Plan.md)

이 두 문서를 고유효과의 현행 기준으로 사용한다. 기존 로드맵, 회차별 리뷰·인계, P4 제안 문서에서 현재도 유효한 요구사항과 검증 결과만 통합했다. 과거의 중간 수치, 이미 해결된 보류 사항, 중복 리뷰는 별도 현행 문서로 유지하지 않는다. 향후 아이디어와 수치는 팀이 확정한 결정으로 취급하지 않는다.

## 1. 목적과 진행 원칙

고유효과는 장비 이름에 어울리는 행동과 선택을 만든다. 무기는 공격·표적 선택, 투구는 행동 순서·자원 관리, 상의는 생존·피격 대응, 부츠는 이동 리듬, 유물은 가방 공간을 사용하는 빌드 변화를 맡는다.

빌드 단위는 **무기 1개 + 실제 장착 가능한 방어구 + 소지 유물 + 기존 스킬**이다. 무기 두 개를 동시에 장착한 것처럼 시너지를 계산하지 않는다. 같은 유물 여러 개의 효과는 기본적으로 중첩하지 않는다. 각 효과는 강한 상황, 약한 상황, 조건이나 공간 비용을 함께 정한다.

기존 PlayerContext·Stat·Buff·상태이상·인벤토리·풀·Mirror 권한 경로를 재사용한다. 실제 첫 효과에 필요한 기능부터 만들고, 범용 Manager·Factory·스케줄러를 미리 추가하지 않는다. 피해·생명주기·서버 권한을 줄여서 코드를 간결하게 만들지는 않는다.

## 3. 현재 데이터 현황

2026-09-20 ItemTable에는 무기 102개, 방어구 41개, 유물 15개로 총 158개가 있다. 고유효과 ID가 연결된 아이템은 52개다. **52개는 데이터 연결 수이며 구현·실플레이·4인 검증 완료 수가 아니다.**

- 위 완료 장비 6개를 제외한 46개는 기존 표 기반 연결이다. 실제 동작과 Mirror 지원 여부는 개별 검증이 필요하다.
- 최초 우선 장비 20개 중 아크 블레이드·인페르노 2개를 완료했다. 아래 남은 18개는 현재 `uniqueEffectId`가 비어 있다.
- 유리빛 궤도와 H3/B1/R2는 그 최초 20개와 별도로 완료했다.
- 효과 표는 데이터 56행이다. 사용 중인 ID 52개 모두 표에 있으며 아크·인페르노·유리빛 궤도도 같은 경로로 재생성한다.
- 미참조 표 항목 `UE_TestHelmet`, `UE_TestGreatSword`, `UE_SturdyArmor`, `UE_HasteAura`는 참조·용도 확인 후 정리한다. 이름만 보고 지우지 않는다.
- `UE_AdvancedCore`의 HELLO WORLD, `UE_CyberneticCore`의 +77은 기존 시험 의도를 확인한 뒤 처리한다. `UE_LuckyCharm` 등 기존 Mirror 미지원 이력도 별도 확인 대상이다.
- Common/Advanced의 공란이나 Rare 무기 24개·방어구 8개의 공란을 모두 새 고유효과 요구사항으로 확대하지 않는다.

## 7. 최종 검수까지 남은 범위

- 여러 PC의 LAN/WAN·지연/손실 환경과 전체 경로 검수. 서버와 별도 Player 4개의 동일·혼합 빌드, 관찰자 수신, 재접속·새 런은 Q1에서 통과했다.
- 보스 전체 패턴 중 상태이상, 정식 Act1 웨이브와 최종 성능. Q1 보스 시험은 실제 보스 씬에서 AI를 정지한 상태의 저항·면역 검사다.
- 공격속도 변화의 Fighter 타이밍, 저프레임·원격·공격 중 속도 변경. Gunner 복귀 블렌드는 측정했지만 임의 조정하지 않았다.
- 고유효과 외 기존 맵의 엘리베이터 앵커 오류와 Full Boss Pipeline의 CampStatusPopup.fireRow 참조 오류는 통합 검수 전에 해결해야 한다.
- 기존 표 기반 46종의 일괄 완료 판정, 신규 후보의 상세 수치·제작, P5/P6는 아직 수행하지 않았다.

## 8. 문서 유지 방법

전체 계획서는 완료 상태·장비 목록·순서만 갱신한다. 상세 계획서는 해당 파트의 동작·파일 연결·검증 결과를 갱신한다. 리뷰에서 새 결함이 나오면 해당 파트의 남은 작업에 넣고, 회차별 새 인계 문서를 만들지 않는다. 구현 사실은 김성우 개인 구현 로그에 기록하며 팀의 확정 결정은 별도 요청 없이 DecisionLog에 옮기지 않는다.
