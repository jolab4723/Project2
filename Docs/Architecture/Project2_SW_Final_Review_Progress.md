## 8. R13 수정 전 재검증 (2026-10-07)

기존 5개 후보 모두 설명 불일치 또는 중요 조건 누락의 근거가 있다. 추가로 융단폭격 강화1의 피해 증가율도 실제 값과 다르다. 현재 값이 설계 의도인지까지 확인한 것은 아니므로, 이 결과만으로 설명 또는 밸런스 수치를 임의 변경하지 않았다.

| 항목 | 현재 표시 | 확인한 실제 동작·데이터 | 판정 |

1차 Editor 검사 경로와 범위(후속 Play 검사는 9절):

- Unity 6000.3.8f1의 `run_script`로 정식 `Gunner.prefab`을 격리된 Prefab Contents에 로드하고 연결된 궁극기 SO를 확인했다. 강화 계산·스택 여부·산탄 IEnumerator·실제 효과 SO의 버프 상한을 실행했으며, 저장 없이 임시 객체를 정리했다.
- `SkillDataLabel.xlsx`의 각 언어 `GunnerUltimate` 행, `UniqueEffectLabel.xlsx`의 위 3개 효과 행, `UniqueEffectTable.xlsx`의 해당 효과 정의를 읽었다. KOR/ENG/JPN/CHN의 검토 대상 JSON 문구와 Unity에 로드된 라벨 SO가 일치함도 검사했다. 잘못된 문구는 생성물만의 문제가 아니라 원본에도 있다.
- 화면 설명 경로는 `SkillPopupController`→`SkillLabelDatabaseSO`, `TooltipUI`→`UniqueEffectLabelDatabaseSO`다. 고유 효과 라벨이 없을 때만 `UniqueEffectSO.EffectDescription`으로 폴백하므로 테이블 설명만 고쳐서는 현재 툴팁이 바뀌지 않는다.
- `SkillData.json`과 `SkillDataSOImporter`는 이 세 강화율을 가져오지 않는다. 현재 실제 값은 스킬 SO에 저장돼 있으며 `SkillDefinitionSO`의 기본값도 15%다. 따라서 설명 55/35/30%로 동작을 맞추려면 라벨 정정과 별개로 명시적인 수치 조정이 필요하다.
- 검사 스크립트 컴파일 진단 없음, Console 새 로그 없음(전후 447건), 원래 `Start` 씬 clean 유지. 게임 코드·데이터·프리팹은 변경하지 않았다. 이번에는 실제 플레이 시전·연타 대상 전환·네트워크 재현·UI 화면 캡처를 하지 않았으며 개인 구현 로그 대상인 구현 작업도 없다.

다음 수정 시에는 스킬 설명 원본과 고유 효과 라벨 원본을 각각 고치고 생성 경로로 반영해야 한다. 고유 효과의 한국어 폴백을 위해 `UniqueEffectTable` 설명도 함께 맞춘다. 융단폭격 강화율과 0.3/0.35초 중 어떤 동작을 목표로 할지는 이 검증 결과와 구분해 결정한다.

검증 방식과 한계:

- 궁극기는 각 케이스마다 새 정식 Gunner에서 `TryUseSkill(3)`으로 시전했다. 정상 애니메이션 이벤트가 실제 스킬 실행을 호출했고, 6개 케이스 모두 MP 150이 소비됐다. 피해 이벤트, 쿨다운, 포탄 생성 시각과 범위 표시 이벤트를 기록했다. 키보드 입력·팝업 클릭 검사는 아니다.

- 테스트 시작 이후 새 Console Error는 없었다. 종료 후 원래 `Start` 씬은 clean 상태이며 게임 코드·데이터·Scene·Prefab은 변경하지 않았다. 로컬 저장 파일 7개는 사전 백업에서 복원하고 SHA256 7/7 일치를 확인했다. Assets 밖 임시 실행 스크립트를 정리했다.
- 로컬 증거: `RunValidation/R13Play_20261007/gunner.json`, `repeated-switch.json`, `scrap.json`, `act1-play.png`. 해당 폴더는 로컬 검증 산출물이며 Git 추적 대상이 아니다. 화면 캡처는 테스트 장면 확인용이며 위 수치는 이벤트 기록에 근거한다.

이 Play 검사 시점에는 **재현 확정·수정 대기**였다. 이후 설명을 현행 동작에 맞추기로 결정해 아래 10절에서 수정했다. Play 검사 자체는 검증 작업이므로 개인 구현 로그에는 추가하지 않았다.

## 10. R13 설명 수정 완료 (2026-10-07)

사용자 결정에 따라 실제 전투 동작과 수치는 유지하고 설명을 수정했다. 강화3도 최종 요청에 따라 15%로 정정했다. 지정 거리와 산탄 폭발 반경은 서로 다른 길이이므로 두 증가율을 더해 단일 사거리 +30%로 쓰지 않는다.

- 산탄 폭격: 0.35초 간격으로 9발.
- 강화1: 피해량이 15% 증가합니다.
- 강화2: 쿨다운이 15% 감소합니다.
- 강화3: 지정 거리와 산탄 폭발 반경이 각각 15% 증가합니다.
- 고철 압축기: 기존 처치당 +0.5% 설명 뒤에 “최대 100회 중첩되며 공격력은 최대 50% 증가합니다.” 추가.
- 코어 브레이커와 초냉매: “다른 적을 적중시키면 누적 적중 횟수가 초기화됩니다.” 추가.

`SkillDataLabel.xlsx` 16셀, `UniqueEffectLabel.xlsx` 12셀, 한국어 폴백용 `UniqueEffectTable.xlsx` 3셀을 바꿨다. 4개 언어를 함께 수정했고 추가 설명에는 가운뎃점을 사용하지 않았다. 기존 Excel 변환기로 JSON을 생성하고 기존 라벨 작성 경로로 DB를 갱신했다. 고유 효과 SO 3개는 설명 필드만 갱신했다. 다른 Excel 값, 서식, 시트 구성과 기존 GUID를 보존했다.

검증: 저장한 Excel 재읽기와 Unity 로드 데이터에서 31개 변경 문구 일치, 4개 언어의 효과 3종 총 12개 설명 치환 성공, 변경 diff가 설명 필드에 한정됨을 확인했다. Unity는 컴파일 대기 없이 ready이며 새 Console Error는 없었다. 9절의 Play 결과를 기준으로 대조했고, 설명 수정 후 UI 화면과 네트워크 테스트는 반복하지 않았다. 로컬 검증 결과는 `RunValidation/R13Play_20261007/labels-updated.json`에 남겼다.
